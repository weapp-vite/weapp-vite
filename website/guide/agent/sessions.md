## 查看与恢复

```bash
weapp-agent sessions
weapp-agent sessions --details
weapp-agent session SESSION_ID --json
weapp-agent resume SESSION_ID "继续处理构建失败"
```

终端在任务开始时显示会话 ID。日志使用版本化 JSONL，写入工具开始记录后才执行工具，完成后保存结果。

`sessions --details` 按更新时间倒序列出会话，`session <id>` 查看单个会话。详情包括最近的用户请求摘要、最后一次运行的状态、步骤与 token 用量、待核对调用及日志异常。没有结束记录的运行显示为 `unfinished`，不代表进程仍在运行。

这些命令不调用模型、不执行工具、不取得写锁，也不修复日志；可以查看正在写入的会话。末尾不完整的一行会被忽略并提示，恢复时在写锁内修复；没有末尾换行但 JSON 完整的记录会正常读取，并在下一次写入前补充分隔符。完整记录损坏则标记 `invalid`，同时保留损坏前可归约的目标、步骤和用量。一个损坏会话不会隐藏其他历史。详情已脱敏，不包含图片原始数据。原有 `sessions --json` 继续输出会话 ID 数组。

## 中断发生在执行过程中

待核对调用分为 `not_executed`（已声明但没有启动记录）和 `outcome_unknown`（已启动但结果尚未落盘）。后者无法凭日志判断是否已经生效。恢复时返回 `action_required`，不自动重放。工具结果已经落盘的调用视为完成，即使后续完成事件尚未写入。

先检查代码 diff、生成文件、运行中的进程以及外部系统状态，再明确确认：

```bash
weapp-agent resume SESSION_ID --acknowledge-interrupted "已核对当前状态，继续剩余工作"
```

此选项为待核对调用补充“未执行”或“结果未知”的记录，提醒模型重新检查；它不会再次执行原调用。确认只对本次恢复生效。

在交互终端中，可以直接输入：

```text
/acknowledge-interrupted 已核对当前状态，继续剩余工作
```

该命令只作用于当前会话；普通“继续”输入不等于确认已核对。不同轮次允许复用已完成调用的 ID，但同一 ID 同时对应多个未完成调用时，日志存在歧义，必须先检查日志，不能用确认选项绕过。

同一会话只允许一个写入进程。恢复时能处理末尾未完整写入的一行；其他日志损坏会报错。

## 上下文与上限

默认最多 40 个模型步骤，总运行超时 10 分钟。较长历史从最旧的非保护消息组开始裁剪；保留下来的工具调用和结果始终配对，调用参数不被改写。最终序列化结果会再次核对预算，避免估算误差超过 `contextCharacters`。摘要不替代原始日志，也不会挤掉用户要求。

压缩完整保留真实用户请求、追加约束和图片，并维持原有顺序。新日志用 `origin: user` 区分用户输入，用 `origin: engine` 标记内部提醒；旧版日志中没有来源标记的用户消息一律保留，因此旧的内部提醒也可能占用受保护预算。

`contextCharacters` 默认是 100,000，表示本地字符估算；每张图片按约 1,792 个字符估算，而不是按 base64 长度计算。这不保证符合模型供应商的 token 上限。

如果受保护内容本身超过预算，引擎在请求模型前停止，返回 `limit_reached` 和 `reason: context_budget`，提示当前与所需预算。调整配置中的 `contextCharacters` 后可恢复会话；用户要求不会被静默截断。达到步骤上限则返回 `reason: max_steps`。工具的 `mutates` 元数据会参与验证门，包括 MCP 和插件提供的写入工具；只要这类工具执行过，即使模型直接输出完成文本，也会要求先调用 `verify_project`。

完整会话保留在本机。根据项目的数据留存要求管理和删除状态目录。
