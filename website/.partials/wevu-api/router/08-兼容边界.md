## 滚动恢复 {#scroll-restoration}

以下四个函数均从 `wevu/router` 导出，与 Router 导航方法分开使用。接入流程和完整模板见 [滚动恢复指南](/wevu/router#scroll-restoration)。

### `createScrollRestoration(options)`

接受 `ScrollRestorationOptions<TRouteMap>`，返回 `ScrollRestorationController`：

| 参数 | 含义 |
| --- | --- |
| `router` | 必填，所属的 `RouterNavigation<TRouteMap>` |
| `onError(error: unknown)` | 可选，捕获或自动恢复失败时调用；省略时输出错误。手动 `scroll()` 的恢复错误由返回的 Promise 拒绝 |

在 App 初始化时、导航前创建一次，同一 router 不允许存在两个有效 controller。只创建 controller 不会自动滚动所有页面，必须由页面或组件注册适配器。

| controller 成员 | 含义 |
| --- | --- |
| `readonly automatic: boolean` | 宿主是否具备自动路由关联能力，不表示某次恢复已执行 |
| `clear(key?: string): void` | 不传 key 清空会话；传 key 清除该路由 key 下全部 id 的快照，并使相关待完成恢复失效；不注销注册 |
| `dispose(): void` | 移除宿主监听、停止所有注册、使待完成恢复失效并清空会话；可重复调用，之后旧 handle 不再恢复 |

### 注册选项与返回值

三个 `use*Restoration` 函数都必须在同步 setup 中调用，共用 `ScrollRestorationRegistrationOptions`：

| 选项 | 默认值与含义 |
| --- | --- |
| `controller?` | 当前已创建 router 的 controller；也可显式传入有效 controller |
| `key?: string \| ((route) => string)` | 默认 `route.fullPath`，包含 query；绑定归属页面时求值，不随业务状态实时变化 |
| `id?: string` | 默认 `'default'`，区分同一 key 下的多个容器 |
| `manual?: boolean` | 默认自动模式；`true` 只捕获、不自动恢复，由业务调用 `scroll()` |

同一原生页面不能重复注册相同 `key/id`；跨页面实例相同 `key/id` 共享快照和数据格式。注册归属按原生页面实例确定，不能用路由 key 或 `routeEventId` 代替页面身份。

返回的 `ScrollRestorationHandle` 包含：

| 成员 | 含义 |
| --- | --- |
| `readonly automatic: boolean` | controller 的能力与当前 `manual` 设置共同决定；`manual: true` 时为 `false` |
| `scroll(): Promise<boolean>` | 等待页面/组件 ready、首屏守卫结算和宿主提交后恢复。活动请求完成返回 `true`；停止、离开、被后续请求取代或失效时返回 `false`。恢复异常会拒绝 |
| `clear(): void` | 清除当前 `key/id` 快照，让同一快照对应的待完成恢复失效，不注销注册或重置画面 |
| `stop(): void` | 注销当前注册并使待完成恢复失效，保留已有快照，不额外捕获；可重复调用 |

`clear()` 后正常生命周期仍可能捕获新快照；需要清除并退出时调用 `handle.clear(); handle.stop()`。正常隐藏时同步捕获但保留注册，生命周期销毁时则在停止前捕获。释放整个应用会话用 controller 的 `dispose()`，不要在每次页面卸载时释放它。

### `useScrollRestoration<T extends object>(options)`

接受 `UseScrollRestorationOptions<T>`，除公共选项外必须提供：

- `capture(): (T & { then?: never }) | null`：在离开/销毁前同步读取内存缓存。返回独立快照，`null` 表示清除；禁止 Promise、响应式活动对象或之后仍会被修改的嵌套引用。框架不会为快照深拷贝，也不会在卸载阶段等待异步查询。
- `restore(snapshot: T | undefined, context: ScrollRestorationContext): void | Promise<void>`：没有快照时收到 `undefined`，首次位置策略由适配器决定。不要修改传入快照。
- `context.route` 是注册所属页面的只读路由；`routeEventId?: string` 来自关联的宿主路由事件，不是持久缓存 key。异步恢复在**每次 await 后、写宿主前**检查 `context.isActive()`；清理只能使请求失效，不能强行中止业务 Promise。

例如，业务列表已提供 `ensureListContent`（准备内容）、`restoreListOffset`（应用位置），并在自身滚动事件中调用下面的 `onListScroll`：

```ts
import { useScrollRestoration } from 'wevu/router'
import { ensureListContent, restoreListOffset } from '@/services/catalog'

const latest = { top: 0, left: 0 }
function onListScroll(top: number, left: number) {
  latest.top = top
  latest.left = left
}

const handle = useScrollRestoration({
  id: 'virtual-list',
  capture: () => ({ list: { ...latest } }),
  async restore(snapshot, context) {
    await ensureListContent()
    if (!context.isActive()) {
      return
    }
    restoreListOffset(snapshot?.list ?? { top: 0, left: 0 })
  },
})
```

这两个业务函数不是 Wevu 导出。一个快照可以包含多个具名位置；复制嵌套数据时只保留恢复所需字段，不要保存整份页面数据或原生实例。

### 内置适配器

- `usePageScrollRestoration(options?: ScrollRestorationRegistrationOptions): ScrollRestorationHandle`：仅用于 WebView 页面级滚动，缓存 `onPageScroll`，通过 `pageScrollTo({ scrollTop, duration: 0 })` 恢复；无快照时为 `0`。Skyline 使用显式 `scroll-view`，不要依赖隐式页面滚动。
- `useScrollViewRestoration(options?: ScrollRestorationRegistrationOptions): ScrollViewRestorationHandle`：用于 WebView/Skyline 的 `scroll-view`，额外返回 `scrollTop: Ref<number>`、`scrollLeft: Ref<number>`、`onScroll(event)`。事件形状是 `{ detail: { scrollTop: number, scrollLeft: number } }`；只更新非响应式缓存。解构 ref 后绑定 `:scroll-top`、`:scroll-left` 和 `@scroll`，并明确容器与内容尺寸。恢复分成当前位置基线与目标值两次提交；无快照时两轴均为 `0`。

内置适配器自行检查活动请求。不要同时绑定优先级更高的 `scroll-into-view`；超出当前内容的目标会被宿主裁剪，`scroll()` 返回 `true` 不代表实际像素位置等于请求值。异步内容使用 `manual: true`，等业务内容稳定后再 `scroll()`。

## 兼容边界

- `forward()`、hash-only 导航和页面栈行为受小程序宿主限制。
- 首屏导航默认是 eager 模式，页面先挂载、守卫异步完成；`initialNavigationMode: 'blocking'` 才会在守卫完成前暂缓首屏。blocking 超时默认 `10_000ms`，超时后自动放行并记录稳定诊断 marker。
- `useRoute()` 必须在 `setup()` 同步阶段调用，不能放在 `await` 之后。
- `useNativeRouter()` / `useNativePageRouter()` 直接面向宿主能力；高阶导航优先使用 `createRouter()` / `useRouter()`。
- 自动滚动恢复要求微信基础库 3.5.5+，完整的 `BeforeAppRoute/AppRoute/AppRouteDone/BeforePageUnload` 四组 `on/off` API，以及字符串 `routeEventId`；低版本或缺少能力时 `automatic` 为 `false`，保留手动路径。仓库 Web/headless 宿主通过显式事件契约接入，不通过伪造 SDK 版本启用。
- 原生同路径 `reLaunch` 的完成事件可能带空 `routeEventId`。仅对已确认的新页面，按相同 `webviewId`、路径、导航类型关联；上下文仍使用前置路由 ID，不接受旧页面或不同非空 ID 的完成通知。
- 自动恢复只在新建页面实例 ready、路由完成、首屏守卫结算和实际宿主提交后执行。`onShow` 不是路由完成；返回保留页、切回保留 tab 和前后台切换不回放快照，原生宿主继续拥有这些页面的位置。
- 快照仅在 controller 会话内存中，可跨页面销毁及同会话 `reLaunch`，不跨冷启动/应用重载。不提供浏览器 viewport、DOM/history 仿真或 Vue Router `scrollBehavior/savedPosition` 契约。
- 所有公开类型见 [Wevu Router 类型参考](/wevu/api/router-types)。
- 详细示例和迁移建议见 [wevu/router 使用指南](/wevu/router)。
