## 状态创建与派生

### `ref()` {#ref}

<!-- api-reference-details -->

**类型签名：** `typeof import('wevu')['ref']`

**运行时说明：** 依赖变化进入 Wevu 调度队列，并最终收敛为小程序 `setData` 更新；模板状态必须保持可序列化。

**示例：** 见 [本组示例](/wevu/api/reactivity#example-reactivity-state)。

- 类型入口：`Ref<T>`
- 用途：创建最常用的基础响应式引用，适合原始值或独立状态。
- 说明：读取使用 `ref.value`；在模板中会自动解包。

### `useAsyncDerivation()` {#useasyncderivation}

<!-- api-reference-details -->

**类型签名：** `typeof import('wevu')['useAsyncDerivation']`

**运行时说明：** 为静态 WXML 暴露显式异步状态，并沿用 Wevu 的响应式、批处理、作用域清理与 `setData` 序列化链路。

**示例：** 见 [本组示例](/wevu/api/reactivity#example-reactivity-state)。

- 类型入口：`AsyncDerivation<T>` / `AsyncDerivationState<T>` / `AsyncDerivationStatus` / `AsyncDerivationContext` / `UseAsyncDerivationOptions`
- 状态：`idle`、`initial-pending`、`ready`、`refreshing`、`error`、`disposed`。
- 刷新：`refreshing` 保留最近一次成功值；加载失败写入 `status/error`，`refresh()` 仍正常完成。
- 清理：自动归属当前 effect scope，也可幂等调用 `dispose()`；清理会取消当前任务、清空值和错误并结束等待。
- 说明：加载函数收到当前任务的 `signal`。新刷新只允许最新 generation 提交，旧任务即使忽略取消也不会阻塞刷新等待。
- 边界：不会像 `computed()` 一样自动收集响应式依赖；依赖变化后由业务显式调用 `refresh()`，也不会让 Promise 进入模板。

### 本组示例 {#example-reactivity-state}

组合深层状态、独立 Ref、同步与异步派生值时，只把可序列化数据交给模板。

```vue
<script setup lang="ts">
import { computed, reactive, readonly, ref, shallowRef, useAsyncDerivation } from 'wevu'

const count = ref(0)
const form = reactive({ price: 20, quantity: 1 })
const sdk = shallowRef<{ refresh: () => void }>()
const total = computed(() => form.price * form.quantity)
const publicForm = readonly(form)
const products = useAsyncDerivation(({ signal }) => loadProducts({ signal }))
</script>
```
