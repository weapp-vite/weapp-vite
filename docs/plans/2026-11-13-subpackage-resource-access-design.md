# 分包输出资源访问校验

`[subpackage]` 按来源命名，不能单独证明产物对引用方可见。同一个物理文件可被主包、多个普通分包或独立分包消费，`originalFileNames` 仍只有一个源位置。

继续由 Vite/Rolldown 负责命名、hash、去重、引用和写出。在输出阶段读取 Vite 的 `importedAssets`、bundler 的 `referencedFiles` 及最终样式 URL，按引用产物与目标资产的实际输出目录校验访问边界。主包只能访问主包资源；普通分包可访问自身与主包资源；独立分包只能访问自身资源。保留已有去重来源检查，覆盖没有消费元数据的插件资产。

无法访问时中止构建，诊断包含引用产物与目标资产的仓库相对输出路径，并建议使用主包公共 `assetFileNames`。不自动移动、复制或手写产物。未启用占位符时保持既有行为。每次构建和每个 output 重置本轮占位符状态。

验证覆盖同一物理文件的 CSS/JS 跨包消费、同包访问、普通路径 opt-out、公共目录、CSS 聚合、query/hash、输出配置与重建状态。以完整小程序宿主构建验证页面样式 URL 和文件存在性；在可用的真实 IDE 上验证正常配置的页面与资源访问，并保留对应 headless 覆盖。最终提交通过定向 ESLint、类型、公开类型、构建与回归测试，再由原生 PR CI 验证当前提交。

实现按命名、来源归属、消费者访问拆分文件，避免单文件超过 300 行。

真实 IDE 的共享 PNG 读取已通过，headless 对照暴露 `getImageInfo` 未接入已有包内资源读取入口。复用同一只读入口修复，并在 simulator 的 Node、browser 单测与 browser E2E 覆盖资源更新、删除、恢复；不改变公开类型。既有 `wxState.ts` 已超过 300 行，本轮只改一处读取逻辑，避免在 PR 中混入无关重构。
