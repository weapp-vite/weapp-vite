# 状态保持开发的资产监听会话归属

## 复现与根因

完整真实 IDE 验收中，`stateful-hmr.runtime.test.ts` 的资产生命周期场景在首次修改图片后协议读取超时，页面实例与输入状态丢失；后续复用同一会话的场景级联失败。独立运行原场景仍失败。原生项目单次保存资产也会重建页面，但原生对照未安装框架的监听规则，因此不能据此豁免框架保状态契约。

三入口编译会话重构移除了构建服务对 `installIdeAssetWatch` 的调用；工具和独立测试仍存在，生产调用已缺失。初始输出能正确写出，资源变化也能交付到磁盘，但 IDE 会额外处理资产事件并重建页面。

恢复调用后，原真实场景的创建、编辑、删除、恢复、连续保存及事件检查全部通过。退出检查还发现，Vite 信号处理直接调用服务器 `close()`，旧 stateful 清理只挂在公开 watcher 上，因而临时规则残留。

## 生命周期修复

- 共享 stateful 会话在启动引擎和写出控制文件之前安装原有资产规则。所有入口共用这一步，多平台项目使用实际 IDE 根目录。
- 规则继续排除 JSON 声明的图标等资产，保留 IDE 文件索引与配置校验；资产内容仍由 Vite/Rolldown 发布。
- 关闭、启动失败和独立 Vite 服务器关闭共用幂等清理；在资源释放后恢复本会话接管的项目设置。借用宿主仍由宿主关闭。
- 不改变真实 DOM 断言，不新增等待、重试或强制重编译，不修改登录、缓存或 IDE 安装。

`session.ts` 已超过 300 行。本次仅补回该会话应有的资源归属与安装顺序；规则计算和配置恢复继续留在已有 `assetWatch.ts`，Vite 关闭协调复用现有生命周期工具，避免在本次修复中重排完整 HMR 调度器。

## 回归入口

`session.assetWatch.test.ts` 通过真实临时配置校验启动前规则、普通/多平台目录、启动失败、直接服务器关闭、重复关闭与借用宿主保留。原两种目录回归在修复前均失败。

相关会话、输出、监听与服务器生命周期共 74 项通过，包 typecheck、公开类型和限定 ESLint 通过。下游前重建 `weapp-vite`。原资产场景 headless 与官方 Stable 2.02.2608080 / 基础库 3.16.3 均严格通过 1 场景、7 DOM 检查点；这是提交前工作树证据。

补齐服务器关闭后，真实 suite 连续通过原生样式/脚本、资产生命周期、后续连续脚本更新三个场景。正常退出以及取消运行后对所属开发进程发送 SIGTERM，均确认原配置恢复、临时规则记录移除。没有关闭宿主或退出登录。

完整验收仍未通过：真实 suite 在第四个 Wevu 模板更新场景缺少预期节点；正式 headless DOM 清单在资产场景通过后，后续脚本更新持续收到 `409 rebuilding`，与真实行为存在差异，需另行定位。另一次误选计算样式场景的 headless 运行也保留为失败，不能作为这些场景的有效能力验证。这些失败均不通过跳过或弱化断言消除。
