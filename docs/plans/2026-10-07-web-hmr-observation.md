# Web 样式 HMR 的读取边界

远端 Node 24 的 `1126.style-hmr` 在第一个组件实例样式更新后，读到另一个实例的空颜色与字号；同提交 Node 22 通过。最小本机诊断在真实组件样式 HMR 前取得节点引用，更新后该旧节点的 `isConnected` 为 `false`，颜色为空；重新定位的新节点已连接，颜色为原断言要求的值。

Playwright 的 `Locator.evaluate` 会先定位节点，再执行回调。这两个动作之间可能发生 HMR 节点替换。测试没有主动缓存句柄，但仍可能在回调中读取已经断开的旧节点。只等第一个组件实例更新，不能证明其他实例已经完成更新。

每次样式编辑继续使用原有 45 秒预算，在同一次轮询中重新定位并读取全部相关目标。所有原有颜色、字号、边距和状态断言保留，额外要求节点仍连接，并检查共享组件的第二个实例也收到新样式。这些读取属于同一轮验收，但不是原子 DOM 快照。永久错误或未更新的目标仍会失败；不增加固定等待，不重复编辑或导航，不改 runtime。

验证结果：Node 22.23.2 与 Node 24.14.1 下完整 issue #1126 Web 测试均为 7/7 通过；Node 24.14.1 下完整 Web E2E 为 17 个文件、122/122 通过，两个变更文件的 ESLint 检查通过。此变更仅调整测试的异步就绪边界，不增加 changeset，也不代表真实 IDE 全量验收已经完成。
