# 自动路由待发布版本与迟到通知

## 失败边界

PR #1195 的 Windows / Node 22 headless 检查在新增原生页面和 Vue 页面时超时。失败现场保留了完整页面产物，但构建 profile 只有原生页面的 create 事件，没有 Vue 页面的来源。

路由目录 watcher 是结构事件的唯一所有者。一次扫描可以提前发现多个已落盘页面；稍后才送达的通知因此不再改变扫描签名。若前一快照仍在构建，新页面尚未进入模块图，通知会被普通模块事件的 `hasModule` 门禁丢弃。

## 选择

沿用 native 构建器已有的 `emittedAutoRoutesSignature`，比较当前扫描版本与最近成功发布版本。只要两者不同，结构事件继续进入现有快照队列，保留原始事件来源和时间。待处理事件仍由原有计时器合批；构建中的迟到事件由现有串行链完成下一次真实发布。

不能根据当前产物恰好存在便为迟到通知补造完成记录，因为无法证明正在执行的构建已消费该通知。也不改变 E2E 的等待文件或来源匹配规则；既有运行时和产物断言继续验证完整语义。

扫描与已发布版本一致时，继续按模块依赖处理没有拓扑变化的事件，无关文件和重复通知不应额外启动快照。

## 验证

- 确定性单测覆盖 create/delete、待合批/构建中两种时序，以及发布追平后的重复和无关通知。
- 重建 `weapp-vite` 后运行原有自动路由 headless 场景，保留新增、删除、恢复和页面可达性断言。
- 通过新提交的原生 PR CI 验证 Windows、macOS、Linux 矩阵，不能复用旧 head 的检查结果。
