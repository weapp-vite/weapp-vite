# Dev 进程清理的身份与完成条件

## 问题

原有 `stop()` 在开始清理时就删除登记，超时也正常返回。根进程收到 TERM 后退出时，仍在运行的后代失去后续清理机会；同一 PID 在 TERM 与 KILL 之间被复用时，也缺少逐进程身份核验。串行执行项目因此不等于前一项目的 watcher 已全部停止。

本次只调整测试基础设施，不改变应用构建、HMR 行为或性能阈值。已有远端产物没有进程采样，不能据此认定进程残留导致先前的 HMR 超限。

## 登记与终止

直接子进程的原生句柄仍存活时，才允许发现并登记进程树。登记项保存 PID、启动代次和可执行文件；根退出后只保留此前已经登记的后代，不重新按旧根 PID、命令名或项目路径发现资源。

发现父子关系时同时记录代次，避免先读取 PID/PPID、随后把复用 PID 的外部进程身份登记进来：

- macOS 同一次 `ps` 输出包含 PID、PPID、启动时间与可执行文件，再通过现有 `readManagedProcessIdentity` 复核。
- Linux 从同一份 `/proc/<pid>/stat` 读取 PPID 与启动 tick，绑定 boot ID，再通过现有身份函数复核；不降级为仅比较命令或秒级日期。
- Windows 用一次 Toolhelp 内核快照保留父关系，再在持有的进程句柄内核验出生时间与可执行文件，过滤 Idle PID 0。每轮信号前按登记 PID 列表批量重查；不逐 PID 查询，也不再为每次查询启动 PowerShell。

每次 TERM/KILL 前重新比较登记身份。已退出或已换代的 PID 不接收信号；身份读取失败、中断、字段缺失或权限不足时保留登记并报告失败。Windows `taskkill` 只接收本轮核验后的明确 PID 列表，不使用 `/T` 扩大范围。

发现期间根已经退出，或取得树后身份查询失败时，保留“后代归属未确认”的候选代次与原始错误。这些候选不获得终止权限。根仍持有时可重新核验；根退出后只读取原候选是否消失或换代，同代仍存活或检查失败就继续拒绝，不能把未建立的登记当成空树清理成功。

身份核验使用操作系统可取得的现有证据，不声称用户态查询与派发信号之间具有内核原子性。macOS 的身份精度保持现有 host 检查契约；PID、启动时间、可执行文件任一变化都撤销该登记项的终止权限。

Windows 查询复用同一份 `windowsKernelQuery.cs`，通过系统 .NET Framework 的 `csc.exe` 编译，只在当前进程/worker 内缓存成功产物的字节。首次冷编译、每次写入可执行文件和查询共享原来的 10 秒预算；不预热、不自动重试、不放宽期限。并发首次调用共享编译结果；编译和每次查询各自拥有私有临时目录，操作返回前等待子进程结束并删除目录，不依赖 Vitest 强制终止 worker 时不会触发的进程退出事件。退出钩子只兜底尚未结束的操作，不保留后台服务或跨进程缓存。编译失败保留本次错误并撤销失败缓存，之后的显式清理请求仍可重新检查；编译、查询或回收失败都不能获得未核验进程的终止权限。

通用 PowerShell/CIM 查询的主线默认预算为 30 秒；这里的 E2E 内核查询、精确 `taskkill` 和 Vitest 内核/CIM 对照显式传入原来的 10 秒较小预算。独立 `process-rows` 探针把通用 CIM 的 `cimQueryBudgetMs` 与内核 `queryBudgetMs` 分开报告，不借通用默认值放宽本次内核验收。

## 完成与重试

并发 `stop()` 共享一个进行中的 Promise。只有登记进程均已退出或不再属于原身份，且 execa 已结束并排空输出，才删除清理登记并缓存成功结果。

清理失败时保留未完成身份，清空进行中的 Promise，允许随后调用 `stop()` 或 `cleanupTrackedDevProcesses()` 重试。根进程的退出回调只更新退出状态和刷新诊断，不提前删除后代清理登记。

IPC 断开前也先登记进程树。优先等待进程自行收尾；宽限期结束后仍按登记身份处理剩余资源。只有 ESRCH 表示 PID 不存在，EPERM 等错误不能转换为成功。原生退出、信号派发成功或等待超时都不能单独充当清理完成证明。

## 结构与验证

`dev-process.ts` 保留启动、输出诊断和并发清理入口。独立的 `devProcessCleanup/index.ts` 管理登记、信号阶段和完成条件，`processes.ts` 负责各平台的发现与身份读取；各文件保持在 300 行以内。

回归覆盖根退出后后代忽略 TERM、发现期间 PID 复用、TERM 后身份变化、清理失败重试、身份查询失败、stdio 排空超时，以及 Windows 批量核验和精确终止。fixture 提供原始进程行而非直接把身份检查 mock 成成功；真实 Windows 用例保留独立 CIM 对照、完整/过滤快照和同命令的外部进程，并验证并发冷查询及 owner 退出后的私有可执行文件回收。

相邻的 stdio 适配器按 encoding 保留文本和二进制 transform 类型，用 tuple 解构保留额外文件描述符；类型断言验证两种配置，输出行为保持原契约。

修改前已记录 13 项中的 6 项预期失败。实现后的单测、受控真实子进程与串行下游验证结果随本次提交记录；本说明不作为全量 IDE 验收通过证明。
