# 静态检查参数预算

全面验证中，Git pre-push 遇到尚未获取的远端旧提交，按既有策略回退全仓范围。把所有文件作为一次 `pnpm exec eslint` 的参数触发了启动器栈溢出，静态检查未能开始。

保留缺失基线时扩大范围的策略。ESLint 与 Stylelint 共用一个文件任务生成器，按包含引号和 UTF-8 编码的参数成本分批，每批保留 4096 字节以内的启动余量。各批仍由现有执行器控制并发、取消和失败汇总；首批保持已有任务名，后续批次使用独立任务名，所有文件按原顺序完整检查。

单纯在全仓 fallback 时改用目录参数不能覆盖普通的大规模变更；修改 pnpm 或绕过 hooks 也无法修复验证器的输入边界，因此采用文件批次。回归测试同时覆盖普通变更和缺失基线，包含带空格和中文的路径，核对无遗漏、无重复及参数预算。现有超过 300 行的计划模块只接入调用，批次逻辑独立存放。
