# 受管 journal 单次扫描与身份校验

完整 headless 验收两次停在任务启动前的历史 journal 读取，分别等待原生文件关闭和目录枚举。固定 Node 的三组实际历史扫描均完成，每组执行 605441 次文件系统调用。该证据证明扫描工作量较大，尚不能确定原生请求不完成的唯一原因，原始未完成结果继续保留。

当前递归在父目录中解析子目录作用域，进入子目录后再次解析同一作用域。第二次解析结果没有再与父快照比较，因此整棵树在子目录枚举期间切换到新的合法作用域身份时，会接受变化后的记录。新增回归用真实临时目录在该时间窗口替换根与子目录的 marker，原实现会返回记录。

将递归提为私有读取函数，每个子目录先检查目录类型，枚举后完整解析作用域，并立即与父快照比较。每次完整扫描中，每个目录只解析一次；原有根、祖先链、真实路径和内容校验保持完整。仅公开顶层的首次枚举允许缺失目录返回空结果，递归节点消失及后续读取失败继续拒绝。无 marker 的 legacy 树保持原比较规则，后续公开调用重新读取所有身份。

不缓存不同任务之间的历史检查。独占机器租约仍允许嵌套借用者创建独立任务根，跨任务缓存可能漏掉被外层捕获的内层清理失败。共享套件根也会扩大安装退出恢复的记录范围，因此每个任务继续使用独立 journal、cleanupKey 与既有恢复边界。源码及新增测试均少于 300 行，无需扩大拆分。

验证先在原实现运行新增测试，再运行修复后的 journal、作用域、所有权与安装恢复回归，以及包级类型、公开类型、最小 lint 和重建。实际历史扫描按相同 Node、历史输入与记录方式比较调用次数和观察结果。完整 headless、DOM、真实 IDE 与新提交的原生 CI 继续独立验收；调用减少不能替代这些结果，也不代表已经消除所有文件系统竞争。
