# HMR 样式输出归属的重复扫描

整仓 classic HMR 的 227 个功能场景通过，但 runtime demo 的六个场景在两轮 CI 中超过既定 1500ms 门禁。本地 CPU 采样显示，样式产物生成循环对每个 owner 都重新解析全部 sidecar 的输出路径，形成随 owner 与 sidecar 数量相乘的同步文件系统访问。八入口的真实 Vite 回归中，每个 sidecar 的输出路径被解析十二次。

在样式预处理全部结束后，为当前 `generateBundle` 建立输出归属索引。owner 内容合并和剩余 sidecar 补发共享同一索引，保留原有来源顺序、物理路径去重和原生 emit 所有权。索引只存在于本轮局部变量中，不跨构建、异步代际或输出配置保存。

不采用跨轮次真实路径缓存，避免软链接改指、登记撤销或输出配置变化后命中过期身份。也不修改性能阈值、基线、场景数量或正式失败策略。先以定向测试验证线性路径解析上界、产物内容、新代登记变化和输出扩展名切换，再重建包并比较同场景 profile，最后在 CI 和正式 IDE 完整验收。

`css.ts` 已超过 300 行。本次将新增索引提取到 `css/sidecarGrouping.ts` 并减少原文件中的重复扫描；暂不拆分整个 CSS 发布流水线，避免把性能修复扩大为生命周期重构。

定向验证：CSS 相关 19 文件、140 测试及包源码类型检查通过。相同本地六场景在原门禁下约 657–670ms；优化前约 677–703ms。该优化确实消除了重复解析，但本地增益较小，不能据此宣称 CI 的 1500ms 性能门禁已修复，仍需原 CI 场景验证。
