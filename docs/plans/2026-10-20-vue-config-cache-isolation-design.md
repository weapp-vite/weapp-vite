# Vue SFC 源码配置缓存隔离

## 问题与证据

`extractConfigFromVue` 在同一编译上下文中缓存并返回源码配置对象。entry loader 首次读取或不能复用自身 HMR 缓存时，直接将该对象传给自动导入增强器。增强器会原地写入 `usingComponents`，因此派生的组件绑定进入了提取器缓存。

最小 source 单测复用了真实配置提取器、entry loader 与自动导入增强器，并固定 SFC 时间戳。首次加载注入自动组件后，再次读取源码配置时能观察到该组件。后续移除自动组件解析结果时，`entry-direct` 路径能从 loader 的独立缓存恢复源码配置；`wxml-importer-import` 路径则再次读取被污染的提取器缓存，继续发布旧绑定。显式声明的组件绑定在两个路径都保持不变。

首次执行这两项回归得到两项失败、五处断言差异；失败记录保留了未经修复的结果。该证据只确认源码配置的所有权缺陷，尚不能证明它解释了 IDE 0137 的最终 JSON 变化或页面重载。

## 方案选择

在 loader 消费配置提取结果的边界复制配置，是本次采用的方案。它沿用原生 JSON 和 loader 暖缓存已有的复制方式，使本次加载拥有自动增强所需的可变对象，提取器与 loader 的缓存继续只保存源码配置。

另一个方案是让配置提取器每次都返回副本，但这会改变所有调用者的分配行为，并将 loader 的派生字段隔离责任扩散到通用提取 API。也可以把自动导入增强器改成返回全新配置，但这需要同时调整原生 JSON、布局与注册资产等调用边界，超出已复现问题的最小范围。

## 数据流与边界

冷加载及非稳定 HMR 的数据流为：提取源码配置，保存 loader 缓存副本，创建当前加载副本，再增强、注册并发布 JSON。稳定 HMR 继续使用 loader 缓存的副本。两个分支在自动增强前都取得独立对象，不修改底层缓存。

普通 `<json>` 块与 JSON 宏都经过同一消费边界。JSON 宏仍保留原来的求值、依赖检查和失效规则；无配置时仍返回 `undefined`，本次加载继续使用自己新建的空对象。该修复不增加新的缓存、失效来源或输出写入路径。

## 验证与交付

回归测试覆盖首次加载、稳定与共享模板触发的暖重载、显式组件保留及派生组件移除，并评估普通 JSON、宏与缺失配置边界。验证按 source 单测、目标文件 ESLint 和包级 typecheck 执行；下游验证须由父任务在更新构建产物后单独串行进行。

现有 `loadEntry.test.ts` 已超过 300 行，本次复用其完整 loader fixture 与模块替身，避免为这条所有权契约复制同一组初始化代码。生产改动仅为现有 loader 消费边界增加复制，没有新增测试专用接口。
