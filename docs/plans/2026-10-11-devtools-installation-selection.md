# 微信开发者工具安装选择与多版本测试

## 行为

安装由用户完成。`weapp-ide-cli` 负责从应用元数据发现 Stable、RC、nightly，登记自定义 CLI 路径，并为 CLI、HTTP、automator、MCP 与 E2E 解析具体安装。列表包含安装身份、配置目录和失效原因；登记不保存渠道、版本或账号数据。

优先级为固定 target、本轮选择、环境变量、旧全局 cliPath、本机最新 Stable。同层路径、渠道、版本必须一致；版本按数字段排序，真实路径去重，同版本多份安装要求显式 CLI。默认选择不访问网络，官方查询提供报告和更新证据，只有显式严格模式要求匹配所选渠道官方最新版本。

每次操作固定安装与 CLI。底层 automator 接收解析后的路径，已有安装身份、端口归属和资源 journal 继续负责会话隔离与清理。

## 矩阵与单账号

`pnpm e2e:ide:matrix --targets=stable,rc,nightly --suite=ide-smoke` 复用现有 suite、筛选和严格策略。默认仅 Stable，全程持有同机同用户串行租约，资源终结后才切换。普通失败、缺失安装和登录失效记录后继续；宿主身份异常、清理失败、OOM、异常 SIGKILL 或取消停止后续目标。

同一微信账号切换安装后，另一安装可能需要重新扫码。用户选择非交互模式：矩阵不等待扫码或自动重试，将失效记录为 `blocked` 和 `runtimeBlocker.code: needs-login`，保留原始原因，继续其他目标并返回非零退出码。可重新登录后单独补测该渠道，无需预备多个账号；不复制 ticket、Cookie 或安装配置目录。

报告区分请求、实际安装和运行时观察，按所选渠道记录官方查询结果。缺少 IDE、基础库、安装身份的 runtime 证据，或 suite 为 partial、blocked、未执行时，均不能计为完整通过。

## 验证记录

- 安装发现、排序、符号链接、歧义、优先级、冲突、离线选择、Windows 注册信息与带空格/中文路径均有单测；公共安装与选择 API 有 tsd 覆盖。
- CLI 分发测试核对包装参数剥离和上传版本透传；MCP/REST 测试核对选择与安装间会话隔离。
- 矩阵与 runner 测试覆盖普通失败续行、登录阻塞续行、官方离线、runtime 身份异常、清理停止、取消和异常 SIGKILL；E2E 环境作用域验证正常与失败后的原值恢复。
- 三个受影响包的 typecheck、公开类型测试和构建通过，路径范围 ESLint 与网站构建通过。E2E 整体 tsconfig 仍包含未修改 fixture 和历史测试的类型错误，不能宣称整体 typecheck 通过。
- 本机串行真实 smoke 已选择 Stable 2.02.2608080 与 nightly 2.02.2610092；Stable 项目导入未获确认，nightly 返回需要重新登录，RC 未安装。两次 task 的资源清理与退出核验完成，未取得目标页面 runtime 证据，最终验收未完成。该局部 smoke 不替代干净主线工作树上的正式全量验收。
- Windows 分支使用平台行为 fixture 验证；本次未在真实 Windows 宿主运行 IDE。

安装选择新增模块均保持在 300 行以内。原有 `wechat-commands.ts`、MCP session manager 和 suite runner 已超过 300 行，本轮保留原分发与资源生命周期边界，仅增加共享选择调用和报告字段，避免同时迁移成熟命令或清理流程；发现、登记、官方查询、上下文和矩阵执行各自拆成独立模块。
