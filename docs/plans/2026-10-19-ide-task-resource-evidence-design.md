# IDE task 资源证据持久化

## 范围与边界

为真实微信 IDE suite 的每个 task 保存独立资源附件，关联 run、提交、task、机器 child scope、journal 和所选安装。该附件仅持久化已有生命周期检查与三个边界上的观察，不改变资源所有权、窗口预算、清理顺序或验收断言，不新增 IDE 启动、查询定时器、内存阈值或自动重试。

headless、普通 CI 和非 IDE task 不启用采样。采样只读取所选安装的进程身份和 RSS，不输出全机命令行或环境变量。无法获得、解析失败或未覆盖的平台记录 unavailable 与原因，不用零或成功代替未知。

## 三个观察边界

1. 冷宿主认领后、task 启动前：记录系统 free/total bytes、认领时已有的宿主快照、journal 和 scope。
2. task 结束、清理前：记录系统内存、所选安装进程树与当时 RSS、journal、登记端口、watcher 和快照目录事件。
3. journal 清理及宿主退出后：记录系统内存和最终 journal，复用原有清理/宿主退出核验的结果，保留原始错误与证据缺口。

RSS 是三个边界中的时点采样，不是峰值；`os.freemem()` 标为 free bytes，不称为 macOS 可回收或可用内存。宿主生命周期返回原检查已取得的结果，避免为附件重复发出 IDE 命令或退出核验。

若收尾时宿主已 cold，则在同一边界补一次只读完整安装退出检查，再确认宿主仍 cold；此路径不派发 CLI、不启动或退出 IDE，也不增加清理权限。两个需要同时持有项目的 suite 在 manifest 中预先声明双窗口预算及原因，父 runner 和直接执行的 suite 使用一致配置；观察到重叠窗口不能自动提高预算。

RSS 清单复用现有内核路径及 text-image 核验层，后者只用于前后 PID 身份仍稳定的空路径，最多四个查询并发，统一十秒派发预算及原查询自身超时；已派发查询全部等待，不遗留采样进程。全机无关条目只保留数量，不输出其映像。无法分类、身份漂移或新增进程使完整安装 RSS unavailable，同时保留已核验成员的小计。采样区间和秒级启动时间的非原子性明确写入报告；这些诊断不能增加关闭权限。

机器 scope 的标识兼任租约能力票据，只保存 SHA-256 供关联，不输出原值或 journal owner token。事件文件仅在本 task 初始化成功后传给子进程；追加不创建新文件，初始化冲突或事件流截断均记录证据缺口。附件复用已忽略的 `docs/reports/dom-acceptance/<runId>/task-resources/`，避免生成源码噪音。

## 窗口与 watcher 语义

窗口字段分开表达：`managedBudget` 是配置预算；`traceDerivedManagedOverlapUpperBound` 根据 journal 的创建意图至双销毁时间区间计算保守上界，创建意图不代表原生窗口已打开；`sampledNativeWindowMaximum` 明确为 unavailable，因为本方案没有原生窗口采样。缺失或不完整的销毁证据保留为缺口，不能宣称原生峰值为零。

snapshot wrapper 仅在原有 watcher 启动、关闭、错误和目录删除边界被动追加事件，不添加 watcher 或轮询。独立窄 helper 承担日志写入，automator 仅接线。缺少显式停止/删除事件时保持未知，不能把子进程退出推导成成功关闭。

## 错误与交付

证据读取或持久化失败不能跳过既有两阶段收尾；journal/scope 清理与宿主退出始终独立尝试。附件记录 incomplete 与错误，不覆盖 task 首错，不新增清理权限，也不通过补写状态伪造已回收。suite 报告增加资源附件链接，路径沿用现有报告目录与脱敏规则。

新增实现按类型、采样、journal 汇总及记录器拆为小模块。现有 `suiteRunner.ts` 和 `automator.ts` 已超过 300 行，本次只增加边界接线，避免继续把诊断逻辑塞入大文件。该变更为 E2E 内部诊断工具，不影响发布行为，无需 changeset。

## 验证计划

增加窄测试覆盖：窗口意图区间与未知证据、时点采样和安装过滤、watcher 错误与停止/删除事件、原有宿主退出检查结果返回，以及采样失败仍完整执行两阶段清理。先运行相关 ESLint 与单测，再由主任务串行执行 IDE 验收。当前全机 E2E 运行期间仅编辑隔离 worktree，不执行测试、构建、安装或 IDE 命令。

## 不安全宿主的调度修复

本轮完整验收暴露出 runner 在宿主认领异常时仅通知可选回调，`allow-failures` 仍继续调度的缺口。将宿主身份异常及未停止命令直接写入 task 的 unsafe reason，并设置 runner 的既有停止标志；保留当前 journal 收尾，未认领宿主不取得退出权。回归同时覆盖有、无回调，确保普通失败继续策略不能覆盖安全停止。
