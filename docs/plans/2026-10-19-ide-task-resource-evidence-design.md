# IDE task 资源证据持久化

## 范围与边界

为真实微信 IDE suite 的每个 task 保存独立资源附件，关联 run、提交、task、机器 child scope、journal 和所选安装。该附件仅持久化已有生命周期检查与三个边界上的观察，不改变资源所有权、窗口预算、清理顺序或验收断言，不新增 IDE 启动、查询定时器、内存阈值或自动重试。

headless、普通 CI 和非 IDE task 不启用采样。采样只读取所选安装的进程身份和 RSS，不输出全机命令行或环境变量。无法获得、解析失败或未覆盖的平台记录 unavailable 与原因，不用零或成功代替未知。

## 三个观察边界

1. 冷宿主认领后、task 启动前：记录系统 free/total bytes、认领时已有的宿主快照、journal 和 scope。
2. task 结束、清理前：记录系统内存、所选安装进程树与当时 RSS、journal、登记端口、watcher 和快照目录事件。
3. journal 清理及宿主退出后：记录系统内存和最终 journal，复用原有清理/宿主退出核验的结果，保留原始错误与证据缺口。

RSS 是三个边界中的时点采样，不是峰值；`os.freemem()` 标为 free bytes，不称为 macOS 可回收或可用内存。宿主生命周期返回原检查已取得的结果，避免为附件重复发出 IDE 命令或退出核验。

若收尾时宿主已 cold，则在同一边界补一次只读完整安装退出检查，再确认宿主仍 cold；此路径不派发 CLI、不启动或退出 IDE，也不增加清理权限。两个需要同时持有项目的 suite 在 manifest 中预先声明双窗口预算及原因，父 runner 和直接执行的 suite 使用一致配置；观察到重叠窗口不能自动提高预算。

RSS 清单复用现有内核路径及 text-image 核验层，后者只用于前后 PID 身份仍稳定的空路径，最多四个查询并发；所有查询共享同一十秒截止时间，每次派发前检查剩余预算，并把剩余值传给已有查询超时。已派发查询全部等待，不使用 Promise.race 遗留采样进程。初始 ps 行是唯一 RSS 锚点；后续行只核验身份及完整性，不覆盖或追加初始数值。采样仍为非原子区间内的 RSS 观察，不是原子内存快照或峰值。

初始映像核验后，只为期间新增的 PID 最多增加两轮核验，总计不超过三轮；每个新身份仅查询一次，不 sleep、不启动 IDE、不因结果未知而重查。新 PID 只有映像有效、身份稳定且祖先链可证明不属于所选安装时，才记为 verified-foreign 并闭合清单。新所选安装映像、其后代、未知映像、未知或成环祖先链、任何身份漂移、持续新增或预算耗尽仍使完整安装 RSS unavailable。初始未知条目后来退出、新未知只在中间清单出现后消失，均不能推断为外国进程；曾消失的 PID 即使以相同秒级启动时间重现也保留身份缺口。后续仅分类外国进程不能补造初始 RSS 的归属。

新增 zombie 不再沿用旧采样器的直接忽略规则；即使其 RSS 为零，也无法核验它是否属于期间新增的所选安装进程，因此保留新身份缺口。初始 zombie 仍遵循原有 RSS 处理规则。结束边界再次核对共享截止时间；即使最后一次查询正常返回、没有新增 PID，达到或超过十秒仍标记预算耗尽，不能因无需继续派发而误报完整。

报告分别保存初始未知数、缺失身份数、新目标成员数、新未知数、新已核验外国进程数、身份漂移数、轮数和预算状态，并为新 PID 记录 PID、PPID、启动时间、首次出现轮次及分类来源。无关进程的映像、命令行和环境变量不输出；不按进程名、查询器后代或命令子串忽略条目。当前只有计数的历史附件无法证明新增 PID 来自采样器还是 CI 监控。采样使用精确的当前 ps PID 排除，kernel/lsof 查询均被等待结束，不应无证据归因于自身查询。完整 RSS 不可用时仍保留已核验初始成员的小计，但不得将其改称 total。采样区间和秒级启动时间的非原子性明确写入报告；这些诊断不能增加关闭权限。

机器 scope 的标识兼任租约能力票据，只保存 SHA-256 供关联，不输出原值或 journal owner token。事件文件仅在本 task 初始化成功后传给子进程；追加不创建新文件，初始化冲突或事件流截断均记录证据缺口。附件复用已忽略的 `docs/reports/dom-acceptance/<runId>/task-resources/`，避免生成源码噪音。

## 窗口与 watcher 语义

窗口字段分开表达：`managedBudget` 是配置预算；`traceDerivedManagedOverlapUpperBound` 根据 journal 的创建意图至双销毁时间区间计算保守上界，创建意图不代表原生窗口已打开；`sampledNativeWindowMaximum` 明确为 unavailable，因为本方案没有原生窗口采样。缺失或不完整的销毁证据保留为缺口，不能宣称原生峰值为零。

snapshot wrapper 仅在原有 watcher 启动、关闭、错误和目录删除边界被动追加事件，不添加 watcher 或轮询。独立窄 helper 承担日志写入，automator 仅接线。缺少显式停止/删除事件时保持未知，不能把子进程退出推导成成功关闭。

## 错误与交付

证据读取或持久化失败不能跳过既有两阶段收尾；journal/scope 清理与宿主退出始终独立尝试。附件记录 incomplete 与错误，不覆盖 task 首错，不新增清理权限，也不通过补写状态伪造已回收。suite 报告增加资源附件链接，路径沿用现有报告目录与脱敏规则。

新增实现按类型、采样、journal 汇总及记录器拆为小模块。现有 `suiteRunner.ts` 和 `automator.ts` 已超过 300 行，本次只增加边界接线，避免继续把诊断逻辑塞入大文件。资源记录器的 `index.test.ts` 增至 313 行，仍保留同一记录器及其共享 mock 在一个文件；新增清单闭合的 274 行回归单独放入 `processInventory/closure.test.ts`，不继续扩大记录器测试的职责。该变更为 E2E 内部诊断工具，不影响发布行为，无需 changeset。

## 验证计划

增加窄测试覆盖：窗口意图区间与未知证据、时点采样和安装过滤、watcher 错误与停止/删除事件、原有宿主退出检查结果返回，以及采样失败仍完整执行两阶段清理。先运行相关 ESLint 与单测，再由主任务串行执行 IDE 验收。全机 E2E 运行期间仅编辑隔离 worktree，不并发执行其他测试、构建、安装或 IDE 命令。

新增清单闭合回归覆盖：无关新 PID 闭合但初始 RSS 不变、新目标及后代拒绝、完整 text-image fallback、短暂新未知、初始 PID 消失后重现、未知/成环/漂移祖先、第三轮仍新增以及所有查询共用递减预算。正式 lsof helper 只增加可选剩余超时，默认行为及十秒上限不变；包级回归覆盖默认、较小预算、上限、非法预算和中断。因触及 `weapp-ide-cli` 源码，下游验证前须重建该包。

候选已通过包级 typecheck、类型契约、构建、4 文件 102 项包级定向单测，以及机器租约内 10 文件 91 项内部 E2E 回归；最后一次清单在截止时间恰好完成和越界完成均保留预算失败。真实 IDE 资源附件仍须随提交后的场景验证，已有运行中的采样缺口不因候选单测通过而改写。

Doctor fixture 的自定义 bridge 在读取真实宿主探针前登记同一安装、项目、端口和 endpoint；CLI 显式使用同一安装。独占新建的缓存只在窗口成功关闭后核对文件身份、版本与内容并删除；已有记录及任何替换、改写均保留，删除失败可重试。14 项文件系统回归及 headless 的 3 个 DOM checkpoint 已通过，真实 Doctor 探针仍待 IDE 验证；headless 不创建或删除会话缓存。

## 不安全宿主的调度修复

本轮完整验收暴露出 runner 在宿主认领异常时仅通知可选回调，`allow-failures` 仍继续调度的缺口。将宿主身份异常及未停止命令直接写入 task 的 unsafe reason，并设置 runner 的既有停止标志；保留当前 journal 收尾，未认领宿主不取得退出权。回归同时覆盖有、无回调，确保普通失败继续策略不能覆盖安全停止。
