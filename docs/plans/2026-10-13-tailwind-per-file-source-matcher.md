# Tailwind 逐文件来源匹配

## 诊断依据

有限负规则合并后，候选提交的单次原生脚本诊断完成两个 edit/restore 周期。
四相 prepare 为 52.76–57.66ms，provider 的剩余等待为 44.30–48.94ms，
占 prepare 的 83.97%–85.89%；patch 为 7.37–8.57ms。

同一 child clock 的 CPU 校准误差为 18.69ms。确定属于 provider 的采样支持中，
`isFileMatchedByTailwindSourceEntries` 占 78.61%，其内部 realpath 占 55.92%，
glob 编译占 10.12%。这些是带诊断开销的采样权重，不能作为函数精确 wall 时间。
patch 的确定 CPU 区间为空，possible 区间还覆盖相邻 CSS 阶段，不能精确分配比例。
本诊断不替代正式平台性能门禁，也不重设原基线、预算或采样策略。

安装的 engine matcher 工厂仅包装逐文件上游函数，不会提前编译规则。
首次文件的原语回归也确认，同一个 base 被原 matcher 解析九次。

## 私有实现边界

来源规则和候选提取仍由上游产生。新增私有 matcher 不进入公开导出。
它使用已安装版本的 `source-scan` 路径工具与 `micromatch`，直接声明运行时依赖，
避免依赖 workspace hoist 或 engine 的传递依赖。

每个文件创建新的目录解析表，key 同时包含原始 base 和上游选择的 path API。
同一文件判断使用该目录首次解析出的真实路径视图；不承诺与另一进程在同一次
同步判断中每两次系统调用之间修改符号链接的逐调用观察完全相同。
目录和文件真实路径不跨文件、回调、批次或异步边界保存。`isOutput` 回调修改条目、
重定向符号链接或创建缺失父目录后，下一个文件重新读取和解析。

文件 path API 由文件与全部条目 base 共同选择，每条规则的 path API 则由其 base
与已解析文件选择。绝对模式按原词法 base 归一化，不能用真实路径替换。
不修改 Windows 大小写、隐藏文件或 relative 包含范围判定。

批次只保存与文件系统无关的 glob matcher，按当前归一化模式作为 key。
必须在规则实际被求值、相对路径非空且未越界后才编译，不能提前使长模式错误发生。
正规则 `some` 后再判定负规则 `some`，保持原短路顺序。
条目数组拓扑来自本轮捕获，字段在每个文件判断时重新读取；有限负规则合并仍保留。

优化只接受普通数组和普通或空原型的 data descriptor 条目。
Proxy、数组方法覆盖、访问器、附加 Symbol 访问器或不明字段类型完整回退上游，
资格检查不能先触发它们的 getter。空来源仍遵循原 helper 行为，根准备入口继续
通过原有 length 门禁保持禁用扫描语义。

CSS 输入、完整候选生成、依赖版本前后检查、缓存签名、所有权与最终提交不变。

## 回归与后续验收

先加入上游 parity 和首冷轮原语回归，原实现仅原语测试失败：同 base 九次而非一次。
修复后首文件仅解析一次 base，后续每文件仍各解析一次；纯 glob 不重复编译。
对照普通和复杂模式、隐藏文件、错误短路、混合 Windows 路径、访问器及 Proxy，
并以同一 matcher 验证符号链接重定向和缺失父目录变化。
真实 core 回归同时覆盖 `isOutput` 之后的来源 base 重定向与最终 CSS 候选。

本轮执行所属包单测、typecheck、已有公开类型检查与范围 ESLint。
后续由主任务重建受影响包，再串行执行 headless、Stable runtime 与固定正式性能门禁。
这些下游验收完成前不宣称 issue 已修复完成。
