# 原生微信 IDE 联合样式更新对照

关联 [#977](https://github.com/weapp-vite/weapp-vite/issues/977) 与 [PR #961](https://github.com/weapp-vite/weapp-vite/pull/961)。2026-09-09 的原生对照已复现新 WXML 文字配旧 WXSS 背景的现象。此项目直接由 IDE 读取原生源码，没有运行 Vite、Rolldown、Tailwind 或 dev server；该结果不能确定宿主内部根因，也不能替代正式 suite 的失败验收。

## 环境与操作

- 微信开发者工具 `2.02.2608060`，实际基础库 `3.17.2`，WebView renderer，启用 `compileHotReLoad`。
- 原生 App 含两个 Page：`pages/style-only/index` 与 `pages/mixed/index`；App 全局 `.base` 定义背景 `#fce7f3`、宽 `200px`、高 `80px`。
- 两页都有静态标题 `Native host control`、`Increment` 按钮和 `Count 0` 文本。按钮增加计数；进入各页后先点击一次，全部更新继续要求计数为 1 和页面身份不变。
- 单样式页首屏存在 `.base.local-priority` 节点。保持 WXML 不变，依次将页面 WXSS 中局部背景改为 `#1f2937`、`#166534`、删除局部规则，连续执行三轮。
- 联合更新页首屏没有局部节点。单次操作同时写入页面 WXML 与 WXSS，新增或修改 `.base.local-priority` 节点文字与对应颜色，再恢复原始两文件；计划同样执行三轮。
- 每次写入后实际查询路由、页面身份、节点是否存在、文字、class、计算背景、宽高和计数，最多观察 15 秒；查询异常单列失败。只有进入第二个独立场景时切页，更新后不刷新、不重新导航、不调用编译预热接口。
- 每阶段保存源码哈希、DOM 采样、模拟器截图及宿主日志。截图协议失败保留阻塞状态但允许继续收集下一阶段；DOM 或业务 runtime 失败立即停止。完整结果不会把截图缺失计为成功。

## 实际结果

| 场景                                  | 结果                             |
| ------------------------------------- | -------------------------------- |
| 单样式页首屏、点击及三轮颜色更新/恢复 | 11 个检查点全部通过              |
| 联合页首屏、点击、首次深色更新        | 3 个检查点通过                   |
| 联合页首次绿色更新                    | 失败，新文字已出现但背景仍为深色 |
| 后续恢复与第二、三轮                  | 未执行                           |

总计计划 22 个检查点，执行 15 个、通过 14 个。失败时实际文字是 `Local style 1 green`，期望背景 `rgb(22, 101, 52)`，实际持续 `rgb(31, 41, 55)`；节点仍为 `200 × 80px`、计数为 1，路由与页面身份未变。截图与实际 DOM 一致，无业务 runtime error/exception。

进一步核对所有阶段保存的 150 份源码哈希均匹配，失败绿色 WXSS 与单样式页三次成功绿色更新的内容完全相同。联合更新失败阶段的 61 次 DOM 采样均为旧深色，其中最后 60 次已呈现新文字。主要宿主日志的增量区间连续：首次深色阶段有 WXSS 编译入口及约 10 ms 后的 executor；绿色阶段收到 WXML/WXSS 变更并进入 WXSS 方法，WXML executor 继续运行，但观察窗口内没有对应 WXSS executor 记录。方法入口不能证明编译完成，仍缺内部任务返回值，不能把配置任务合并等候选当作确定根因。

启动日志收集遇到一份旧日志在读取前轮转删除，记录为独立采集错误；这不改变绿色阶段实际 DOM 失败，但意味着不能宣称宿主日志完全无缺失。本次是诊断运行，工作区含待提交修复，不作为最终提交的通过证据。

Computer Use 同时读取了原生项目的 `pages/mixed/index` 与 Console：界面显示更新文字及计数，调试面板显示 0 errors、7 warnings。警告包括灰度基础库与预加载资源提示。Console 无 error 不能替代计算样式断言。
