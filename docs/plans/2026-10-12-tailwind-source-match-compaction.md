# Tailwind 来源规则的有限结构合并

## 问题与验收边界

当前批次的 `prepareTailwindRoots` 对完整封存输入逐个调用上游来源 matcher。
TDesign 的纯编译器复现中，41 条规则共用一个 CSS `src` base；对 251 个候选文件，
上游调用真实路径解析 1651 次，其中 1400 次都用于同一 base。
本机 CPU 的保守 provider-wait 窗口也主要落在这类 base 解析中。
此集合不是活动 HMR 输入的完整记录，原语次数和带诊断扰动的 CPU 结果不能替代正式性能门禁。

目标是在首次冷轮就减少同目录的重复匹配，不增加跨批次缓存，也不改变候选提取、
封存来源、扫描范围、依赖版本检查、所有权和最终提交路径。
Linux 已确认的回退仍须在固定基线、原样本数、原确认策略与原预算下验收。

## 设计

规则仍由上游 `createTailwindV4CompiledSourceEntries` 产生，结果仍由上游 matcher 判定。
仅在私有模块中合并连续、相同原始 base、相同固定结构的负规则：

- `**/a/**` 与 `**/b/**` 合为 `**/{a,b}/**`。
- `**/*.css` 与 `**/*.scss` 合为 `**/*.{css,scss}`。
- `**/a.json` 与 `**/b.json` 合为 `**/{a.json,b.json}`。

字面部分只接受 ASCII 字母、数字、下划线、点及连字符；任何连续的 `..` 均不合并。
相对前缀、绝对模式、转义、已有大括号、逗号、extglob、其他通配形状及不明规则原样保留。
合并模式不超过 8192 字符；只有一个不同字面的组以及超长组保持原条目和顺序。
不得跨越未合并规则，避免提前命中后跳过原先应发生的异常。

`**/`、文件名中的 `*.` 和目录末尾 `/**` 必须留在大括号之外。
将完整 glob 放进大括号会改变 picomatch 的零目录与隐藏文件语义，不能作为等价变换。

每次文件判断从本轮已经捕获的条目重新产生合并视图，再调用原 matcher。
没有真实路径缓存、布尔缓存、全局状态、额外 watcher 或新公开 API。
原 `isOutput` 回调的调用顺序和次数不变；回调修改条目字段时，下一文件会看到修改。
本轮条目数组拓扑仍由原上游输入捕获，不能从新的 root 数组重建。

## 验证

先以原 matcher 对照普通、根层和嵌套路径、显式包含的隐藏文件、忽略目录、扩展名、
复杂模式回退、Windows 路径字符串、错误短路顺序和条目字段变化。
以相同输入统计真实路径解析调用，证明首次判断即减少重复工作，不依赖预热。

随后用真实 core 检查内存源码生成的 CSS，与 fresh 结果及原有 edit/restore、删除、
扫描范围、预处理依赖、重登记和 dispose 回归一起验证。
执行所属包 typecheck、公开类型、范围 ESLint 和重建后，再串行运行现有 headless 场景。
CLI 和下游验证必须加载刚重建的 dist。

正式性能、跨平台消费者和真实 Stable runtime 的结论分别绑定最终提交。
规则对齐、原语次数减少和 headless 通过均不代表这些门禁已经通过。
