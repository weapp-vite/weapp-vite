# 编辑序列资源采样边界

## 问题与证据

全量 CI E2E 的 stateful 编辑序列出现 `Timeout` 中位数 `0 → 1 → 0.5`，触发资源增长门禁。逐次更新的诊断记录确认，采样时仍待执行的短计时器来自 HMR bridge 的 `endUpdate()`，用于恢复生命周期标记。构建完成和一个 `setImmediate` 不保证这个零延时回调已经执行。

## 设计

在测量工具的资源采样前等待一个新注册的零延时计时器，建立已有即时回调的执行边界。该等待位于编辑耗时测量及强制 GC 之后；等待完成后重新检查取消信号，再发送测量结果。

保留同步资源观察接口，新增异步采样接口供 worker 使用。继续统计全部存活资源，保持现有趋势阈值和失败条件。该边界只保证此前排队的即时计时器已经执行，不承诺递归异步任务完全静默。

直接调整真实 runtime 的生命周期时机会改变宿主行为，不适用于这项测量问题；放宽 `Timeout` 阈值会掩盖真实遗留资源，也不采用。

## 验证

- 独立 Node 进程验证即时回调在采样前完成，同时长期 ref 计时器仍计入资源。
- 验证长期计时器增长仍被原有资源趋势门禁拒绝。
- 重跑原始 classic/stateful 资源窗口用例及完整编辑序列，再运行全量回归。

本变更仅涉及测试测量工具，不改变产品 runtime，无需 changeset。
