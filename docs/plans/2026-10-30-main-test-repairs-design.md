# 主线完整测试暴露问题的修复

完整 CI E2E 的 128 个适用任务执行完毕，127 个通过，共享依赖热更新的来源关联检查失败。保留完整报告后，以未修改的测试再次复现，并在测试清理前只读备份原始 JSONL：页面直接编辑有来源事件，共享依赖已写入产物，但该轮 `sourceEvents` 为空、`correlation` 为 `unknown`。

classic 构建只在实际输入版本得到证明后认领来源事件。普通共享脚本由 Vite 默认 loader 读取，未经过已有的入口 reader，因此缺少输入观察。修复在现有 core 的 pre transform 中通知同一观察链，使用该 hook 实际收到的代码；不读取后来的磁盘内容，不接管 loader、调度或产物写出。已有入口继续由原始 reader 提供版本，普通模块通知也不扩大原生入口收集器的分类。

观察路径在没有订阅者时立即返回。物理入口登记负责排除已包装的入口，不能仅按 basename 排除同名的普通脚本。虚拟模块、query、fragment 和 Vue 请求保持各自原有读取边界。更早的用户转换若已改变字节，无法匹配来源版本时仍保留未知，不补造关联。

另一项失败来自 Windows Node 22 覆盖率分片：原生 CLI 测试首例在 20 秒启动就绪门禁处超时，子进程输出为空；同文件第二例和其他平台均通过。现有证据不足以证明具体冷启动阶段或保证增加预算即可通过。候选将首次源码 CLI 启动预算独立为 60 秒，后续三次发布仍各 20 秒，自然退出仍为 90 秒，单例总预算为 240 秒。

首个 preload 使用仅依赖 Node 内置模块的 JavaScript，随后记录观察器启动及 shutdown 模块导入阶段。父进程保留 spawn、error、exit、close、stdio 和耗时诊断；所有原业务与自然退出断言不变。失败时只终止本测试的子进程，最多等待 10 秒确认退出和流结束；无法确认时保留 fixture，并同时报告原错误和清理错误。

本地候选首次复测发现父端主动断开 IPC 后，Node 即使已发出退出及两条流结束，也可能不发出 ChildProcess 的 close。内置 Node 的最小复现不依赖 Vite，确认同一行为。因此终态门禁保持真实 exit 与 stdout、stderr 的 finished 共同完成，close 仅用于诊断；不以 close 缺失否定已经完整观察的退出，也不放宽流排空或失败收尾。

回归首先覆盖输入观察、入口去重、上下文隔离、发布版本及原生入口分类。原共享依赖 E2E 的关联断言保持不变，重新构建 weapp-vite 后验证直接编辑与共享编辑。Windows 候选必须由新的主线原生 CI 验证，不能沿用旧提交或另一个 startup-fallback 场景的结果。局部通过不替代剩余完整 E2E 与最终真实 IDE 验收。

新增观察实现和测试放在 transform 目录，避免继续扩展已有超过 300 行的 transform 测试文件；本轮其他改动文件仍控制在 300 行以内。
