# 零售 E2E 的项目与报告隔离

完整真实 IDE 运行的 136 个适用任务、368 个适用用例和 1410 个检查点均通过，但最后的输入与工作区检查拒绝验收：零售 parity 测试将启动设置及基础库版本写入原模板，JSON render 测试还在未受管的目录生成截图。原运行继续保留为 incomplete，不以事后清理代替门禁通过。

## 项目所有权

零售 parity 为原生应用和 Wevu 模板分别创建独占副本，保留源文件和配置字节，过滤构建目录与缓存，逐个链接已安装依赖的真实目标。构建与 IDE 启动仅操作这些副本，现有 SDK 和启动参数语义保持一致。

未采用会话结束后覆盖原配置的方案，避免恢复逻辑误覆盖原项目上的其他修改；也不扩大修改全局 automator 的 SDK 优先级或所有调用方。原模板与原生应用仍是夹具内容的唯一来源。

每次调用 runtime 启动前，先为副本取得独立 hold；只有返回的会话成功关闭才释放。启动被拒绝、未返回会话或关闭失败时，hold 继续保留，副本清理明确报错，供外层所有权恢复使用；不能因 session map 为空而推断启动资源已经终结。清理已经开始后拒绝新 hold，释放操作幂等。

确认会话关闭后再删除副本。目录清理绑定创建时的文件系统身份，保留被替换的未知目录或链接。并发清理共享结果，失败后允许再次清理。两份副本按顺序完成构建，避免一项构建失败时，teardown 删除另一项尚未结束的构建目录。

## 报告所有权

真实 IDE 截图沿用本轮 DOM 报告目录，文件名带随机标识；独立运行使用既有 DOM 报告默认目录。截图失败仍使原测试失败，不新增忽略规则，不改变页面断言。

## 验证

真实文件系统回归覆盖源文件和配置不变、依赖链接、未知目录替换、部分构造失败及清理重试；runtime hold 回归覆盖等待中的启动、启动拒绝、关闭完成前后的清理门禁和清理开始后拒绝新启动。随后串行运行相关 headless 与真实 IDE 场景，核对源项目与工作区不变；修复提交至同步的 main 后，从头执行原始严格完整 IDE 入口并检查终态。

parity 测试原文件已超过 300 行。本次将新增项目所有权与文件系统回归放在独立 helper，避免继续增加复制与删除细节；未在此次污染修复中重构原有页面对照算法。
