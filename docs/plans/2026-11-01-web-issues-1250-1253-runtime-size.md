## 成本归因与优化

同步 wx 全局安装保留新增的官方 API。minimal-app 和 public-app 的 7,624 B 净增分别来自音频 4,577 B、宿主兼容 API 1,649 B、本地日志 850 B、完整空指标性能对象 421 B、安装接线 24 B、Canvas 节点及查询接线 103 B。没有通过异步 API 或缩减公开入口改变测量契约。

页面阶梯还保留统一 touch 流、刷新状态与外观、受控同值提交及来源追踪、手势组件接线和 legacy DOM 所有权更新。后者避免父组件 setData 在原生点击传播中替换子树，并保留节点身份、原生组件维护的 DOM/样式和输入值；其成本属于正确释放事件资源所需的生命周期边界修复。

触摸协调器和刷新状态机从多个私有成员的 class 改为闭包工厂，保持状态封装与资源释放顺序。最终 ES2018 production 页面阶梯各减少 2,865 B，其中协调器 1,106 B、刷新状态机 1,755 B、调用点 4 B。完成该优化后，legacy 生命周期修复另增加 typical/complex/public-page 各 4,622 B、full-provider 5,289 B。

逐模块比较使用有符号差值，包含删除、替换及现有依赖保留变化；各阶梯模块贡献净和均等于产物净差，未归因差额为 0。#1251 的编译诊断和 polling 修复没有进入浏览器运行时；未发现编译器、AST 或构建元数据的意外滞留。普通阶梯和完整 Provider 的依赖保留不同，分别使用各自实测值。

## 预算与验证边界

```text
新能力锚点 = 原能力锚点 + 已审计新增能力净成本
ceiling = ceil(新能力锚点 × 105 / 100)
当前产物 - 新能力锚点 = main 产物 - 原能力锚点
```

原锚点继续包含此前 #1256/#1254 已批准的能力分项。该公式保留 main 已占用的增长额度，没有把当前产物重设为基线。六个小程序平台、reactivity-core、原微信 legacy ceiling、完整矩阵检查及全部 retained-module deny 规则保持原值；本次仅更新六个受影响的 Web 能力分项。

复现沿用 #1064 的双 checkout 同口径命令和 `validate-wevu-runtime-size.yml`。原始 baseline/current、模块图和差分报告由 PR 原生 CI 的 `wevu-runtime-size-report-full` artifact 保存。门禁继续检查超限、缺项和模块违规，不因新增能力额度放宽 deny。

体积验证不替代功能验收。Web 单测、公开类型、真实浏览器场景、headless 刷新和真实 DevTools 的观察及环境限制分别记录在 PR 中；真实 IDE 自动化未进入目标断言的轮次不能计为通过。
