# CI 与连续 HMR 回归修复

## 支持文件与路由扫描归属

Workspace HMR 的功能场景通过后，仍须独立满足输出范围和耗时预算。快照编译与独立分包拥有隔离的编译上下文，但支持文件应由活动开发服务维护。只在候选扫描阶段禁止写入不足以覆盖配置加载、插件回调和构建收尾。

快照与独立分包现从配置加载到 Vite 构建完成都使用各自服务的 `runWithoutOutputWrites` 作用域。真实集成测试检查四类支持文件的内容及修改时间保持不变，同时确认 WXML、usingComponents 和活动服务后续写入仍正确。普通 JSON 宏不再触发无关自动路由刷新；真正导入自动路由的宏保留原有同步。

## 连续更新的状态新鲜度

旧 HMR bridge 按“与默认值不同的字段数”选择快照。新代码改变默认值、删除字段或用户主动恢复默认值时，该数量可能下降，使已呈现的计数 4 被旧快照 2 覆盖。

每次更新开始前捕获当前宿主数据；仅在实际补丁事务内冻结已有快照。生命周期抑制窗口与快照事务分开，避免同一事件循环内连续更新读到上一轮状态。回归覆盖默认值变化、用户重置以及连续补丁。

Wevu 原先在建立渲染差量基线后直接删除普通 setup 字段。第二次补丁的普通文本未变化时，差量同步不再提交该值，导致文本消失。修复保留宿主数据基线，并只恢复 ref/reactive 绑定；普通 setup 值采用新代码。

真实 IDE 检查首次挂载、模板往返、混合脚本/模板更新、再次混合脚本/样式更新后的计数、store、输入和文本。模拟器 Node/browser 场景使用真实 Rolldown 生成的连续补丁，验证计数 `2 → 4 → 4 → 7`、还原后继续递增，以及父子实例身份和输入。模拟器目前没有 IDE 的真实 HMR 请求与更新文件自动加载流程，等价场景显式交付补丁；直接运行 IDE transport 套件的能力阻塞不记为通过。

## Web runtime 前置依赖

前置代码不能反向注入初始化器及其同步依赖；被前置代码引用的初始化器也不能同时内嵌进 app 再执行一次。产物依赖分析使用 JavaScript 语义，兼容合法 CommonJS 与 ESM。

Web API 注入只为模块未声明的名称生成绑定，保留模块自己的函数、解构绑定及导入。执行回归证明旧代码会把模块自有 `fetch` 覆盖为未初始化占位函数。显式空绑定集合不再回退成全量注入，框架内部的占位绑定可在后续安装阶段更新。

`stateful-hmr` 保留原有 `appPrelude.webRuntime` 配置，classic 启动与 stateful 更新均验收该组合。构建产物始终由 Vite/Rolldown 写入。
