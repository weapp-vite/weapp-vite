# 原生进程清单的终止证据

真实 IDE 全量验收中，doctor 的页面、交互、导航和 runtime probe 均通过，但资源采样将三个已经终止的进程记为未知或身份变化，严格运行器因此停止。保存的四帧原生证据包含三种顺序：准备帧已是 zombie 后消失；锚点是已确认的外部活体，闭合帧变成同实例 zombie；闭合帧首次出现且之后始终为 zombie。

修复增加独立的终止证明，不将这些进程归类为外部进程，也不推断窗口或安装所有权。同帧前后 sysctl 必须确认同 PID、启动时间、父进程和 UID 的 zombie 身份，双映像查询及 task 查询必须全部明确返回 ESRCH、无映像和 RSS。必须还有后续固定帧确认，只允许同实例 zombie、完整退出证据或缺席；最后一帧才出现的 zombie、任何活体返回、PID 复用、权限错误或部分成功都保留阻断。

若终止前观察过活体，该活体还必须从准备帧到唯一 RSS 锚点具备完整、稳定的外部映像及祖先链证明。观察到所选安装或后代、未知活体、映像或身份漂移均不能取得终止豁免。原始帧、缺口和身份变化保持原样；新报告单独记录终止证明及首次阶段，只从不完整计数中排除具有完整证明的项，不补写或替换 RSS。

不采用忽略所有 zombie、等待固定时间再采样或仅因最终消失便通过的方案。回归测试覆盖上述三种顺序及所选安装、未知活体、身份漂移、权限错误和活体返回等反例。随后进行 E2E 工具类型检查、相关单测及真实 IDE doctor 验证；正式全量仍从干净的最新 main 原入口执行。此改动属于验收基础设施，不修改产品运行时或要求系统配置。

新证明模块独立保存，既有清单观察与报告模块继续保留原职责，不为此重构无关文件。
