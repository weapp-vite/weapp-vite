# 导航根节点查询预算修复

真实 IDE 的 button-only 页面出现导航后根节点等待超时。现有实现先等待 `view`，不存在时会用完整体预算，后续节点的协议查询仅剩 1 ms。已有同步拒绝的 mock 未覆盖这个异步边界。原始失败没有逐选择器计时，因此该静态缺陷与真实失败之间的唯一因果仍需运行验证。

目标是保持原有路由比较、1500 ms 导航后预算、300 ms 同路由快速路径、导航次数和最终页面断言，同时使“任一合法根节点已渲染”的条件拥有完整查询预算。显式根节点限定其路由；缺失显式节点不能由通用内容替代。取消发生在异步查询期间时不得返回就绪。

首选候选是通用根节点使用已有的 `*` 选择器；多个合法显式根节点使用一次 CSS 选择器并集查询。先按原源码运行异步回归，再应用候选。真实 Stable 对通配符和选择器并集的支持仍须验证。无效选择器可能使整个并集失败，未验证前不能声称与任意字符串数组完全兼容。

另一方案是逐选择器平分剩余预算，但短预算与 SDK 的轮询间隔相互影响，并会保留串行探测。新增 SDK 批量等待 API 能表达同一条件，但会扩大公共 API、类型和 provider 的修改范围；只有现有选择器能力不足时再采用。

测试在每个用例动态导入前清除模块缓存，并固定实现实际使用的 `WEAPP_VITE_E2E_RELUNCH_SETTLE_DELAY=260`、`WEAPP_VITE_E2E_RELUNCH_READY_TIMEOUT=30000` 及同路由快速路径开关。teardown 逐键恢复原环境（原先不存在的键删除），再次清除模块缓存；不使用静态实现导入，避免继承先前缓存的超时或把固定常量留给其他用例。

默认 `pnpm test` / CI 的 `e2e-hmr-infra` 使用明确 include 清单；本次在 `vitest.config.mts` 中、相邻 automator 条目处登记 `automator.rootBudget.test.ts` 和同步更新的 `automator.relaunch.test.ts`，确保预算与路由限定回归进入默认验证，不扩大 utils 的收集范围。

回归使用假时钟模拟查询超时和成功查询的异步响应，覆盖 button-only、text-only、显式首项缺失、全部查询缺失、显式根隔离及取消；跨路由根限定继续由现有 `automator.relaunch.test.ts` 覆盖。断言 Promise 在推进假时钟前接管拒绝，排空后仍原样等待和抛出，避免原版红测额外产生未处理拒绝。随后按机器租约串行验证相关 headless 和同 Stable 原场景，保留原 checkpoint、超时和断言。当前全量 IDE 运行结束并通过独立资源核验前，不执行这些测试，不修改根工作树。

本轮 `wevu-runtime.pruning.test.ts` 的首屏和响应式更新已经通过，随后 `reLaunch('/detail/index')` 在通用根探测处超时；分包源码只有一个 `<text id="pruning-detail">`。调用方的显式 `text` 根仅限定首页，所以分包会进入上述通用逐项探测。该独立场景进一步支持验证 text-only 异步预算边界，但仍需在同一 Stable 上重跑原场景，不能把静态关联当作已证明的唯一根因。

原版异步预算回归实际得到 7 个失败和 3 个通过；候选使这 10 项通过。旧路由回归的 mock 只接受单个精确节点名，本次补齐其通配符和选择器并集语义，通用根断言验证不会携带首页专属根；原导航次数、当前页面、缺失根拒绝和关闭次数保持断言。异步断言在推进假时钟前接管拒绝，排空后原样等待，防止断言失败另产生未处理拒绝。

`automator.ts` 已超过 300 行。本次保留根探测与导航调用方相邻，以直接核对共享预算、路由限定和取消传播；没有新增公共 API。提取整个启动或导航模块会扩大这次缺陷的改动面，后续可在独立重构中处理。

静态审查发现，将包含无效 CSS 的显式根数组合成并集后，headless 会立即拒绝整个查询；历史 fallback 的外层 catch 又会在第一项抛错时跳过后续合法根。现将 fallback 的错误隔离到每个 selector，下一项仍使用同一轮剩余预算，且在单节点查询前重新扣除多节点查询已消耗的时间；预算耗尽后不再派发下一次查询。不新增逐项 `waitForRendered` 或各自完整等待预算。回归复用 headless 的实际 selector 解析函数，覆盖首项无效、后项有效的同路由/实际导航，以及 fallback 成功 IPC 期间的取消。

原全量 IDE runner 已结束，独立资源核验通过后，本候选经机器租约串行验证：默认 `e2e-hmr-infra` 项目的 4 个相关文件共 58 项通过，包含新增的 13 项预算回归；1072、1126–1128 和 runtime-pruning 的原 provider-compatible 场景在 headless 下共 9 项、31 个 checkpoint 全部通过，没有跳过。相关 ESLint 和 E2E TypeScript 检查通过。同一 Stable IDE 原场景尚待主干验证，这些结果不代表最终真实 IDE 验收通过。
