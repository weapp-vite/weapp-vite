# 推送前检查耗时优化

最近一轮推送只修改 Git hook 及其测试 fixture，却因输入归属缺失选择了全部 workspace，并运行 44 个包的构建和类型检查。优化先修正可证明的检查归属，继续保留未知输入、锁文件和全局配置的保守范围。

在 `scripts/verification/rootTooling.ts` 维护精确的根工具输入与契约测试映射，影响范围分析和任务规划共用该映射。已审计的 hook 输入执行 `gitHooks.test.ts` 和 `check-changeset-frontmatter.test.ts`，覆盖共享 fixture 的直接及间接消费者；混合包源码修改仍保留包级检查。删除及 rename 的旧端继续参与归属，未知新端扩大范围，缺少必需契约时明确失败。

清理锁文件中一条无入边、不可达的 peer snapshot，使仓库锁与 pnpm 已生成的安装锁一致。所有 importer、包解析、完整性、共享 snapshot 及包管理器文档保持不变；随后用原生 frozen install 验证。依赖借用仍使用完整锁比较，不新增忽略差异的规则。

暂不调整环境指纹、回执复用条件、任务并发或构建缓存策略。回执继续绑定候选提交、基线、工具链、环境、拓扑及策略；失败、取消或缺少适用检查时仍拒绝复用。

验证包含精确 hook 范围、共享 fixture、混合包修改、未知及全局输入、删除、rename、缺少契约，以及已有快照和回执边界。通过同一组原始变更路径对比检查清单，再记录实际契约命令和原生推送的耗时；局部检查结果不替代 CI 或完整 E2E。
