# WXML 路径式编辑与 entities 升级

## 目标与基线

在 `@weapp-vite/wxml` 中提供适合复杂模板转换的路径式编辑：父子导航、进入与退出访问、即时查询、局部遍历，以及插入或替换后继续编辑新节点。同时将直接依赖 `entities` 从 `^8.1.0` 升级到执行时 npm 最新稳定版 `9.0.0`。

本任务开始时的基线为 `8ea555238`，位于本地 `main`，领先当时的 `origin/main` 一个提交，工作树干净。该提交属于既有平台解耦工作，本任务在其上增量修改，不改写已有提交或历史验收结论。

## 兼容与模型

- `edit(document, callback)` 保持原有快照语义：`handle.node` 指向输入节点，本轮不自动访问插入或替换出的片段。
- `edit(document, visitors, state?)` 使用路径式会话：`path.node` 反映当前逻辑树，所有修改仍通过受控方法完成，输入文档不变。
- 当前语义节点不携带看似实时、实际属于旧源码的范围。输入节点可通过 `originalNode`、`originalRange` 查询来源；新增节点没有输入文档范围。提交后统一生成新文档及其完整范围。
- 访问器支持全局 `enter/exit`，以及 `Element/Text/Comment/Cdata/Declaration/Script` 分型访问。路径提供父子和兄弟导航、祖先查询、当前属性读取、`skip/stop/requeue` 及子树遍历。
- 插入、替换返回新路径；会话维护当前子列表和遍历队列。删除或替换祖先后，旧子树路径失效；会话结束后全部修改能力失效。
- 普通字符串、表达式、raw/script 边界与源码保真的既有约束继续适用。旧回调路径不承担新增编辑树和导航索引的成本。

## 实现评估

路径模式让遍历、查询和修改共享同一棵会话树，适合按父级条件改子节点、退出阶段统计以及继续转换新节点。`walk` 保留为只读分析入口；函数回调模式保留原有轻量补丁流程。路径模式需要建立完整逻辑树，并在提交时重建公开 AST，以保证当前值、路径身份和最终源码范围各自有明确归属。

当前节点为只读语义视图，修改通过方法完成。结构方法接收源码片段并返回路径，沿用解析器的方言和校验能力。新增能力包括路径导航与 visitor 控制；JavaScript 作用域分析、绑定管理和 AST builder 不在本次范围内。

自动访问新结构时，生成代数同时继承修改目标和活动 visitor 的来源，包含嵌套遍历与 raw 标签重建。单链最多 1024 代；显式重新入队按单路径限制次数和无修改重复次数。该预算不累计原始模板节点数，独立生成和深层输入仍可完成。

`entities@9.0.0` 保留本包使用的同步 `decodeXML` 及 ESM 导出。上游编码和流式接口调整不涉及现有调用；Node `>=20.19.0` 的要求低于本包已有基线。升级继续采用 XML 实体规则，新增回归覆盖数字实体、未知实体、重复解码和模板绑定边界。
