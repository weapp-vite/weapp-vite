# IDE 项目窗口回收

本轮全量回归出现多个测试项目窗口残留，持续占用模拟器内存和 CPU。用户强制退出 IDE 后，先修复资源生命周期，再恢复验收。验收版本仍为用户指定的 Stable `2.02.2608070`，官方版本查询及显式版本例外报告保持不变。

## 根因

连接断开只释放 WebSocket，不能证明项目窗口关闭。启动失败、迟到连接及 worker 退出都可能发生在窗口已经打开之后。日志收尾曾用同一状态阻止后续 `close()`，父任务又没有窗口所有权记录，因此窗口会跨 suite 累积。

## 实现边界

- 受管测试使用所选安装的官方 `agent start`，依据 `openedProjectWindow` 区分新建和复用。直接项目及 HMR 保留原项目目录语义。
- 启动前向任务专属 journal 写入 intent。只有确认新建并核验宿主身份后才授予关闭权；缺失回执不能靠路径猜测所有权。
- 窗口所有权独立于连接状态，记录安装、项目、端口、监听进程 PID 与启动身份。监听进程可能是 IDE 后端，不能冒充窗口身份。关闭前复核身份，通过精确 `close --project` 请求后，等待本次窗口实际销毁及所属端口释放。
- 已释放记录不能再次关闭同路径；复用的手动窗口不属于任务。失败清理保留记录、允许重试。
- worker 和父任务均执行收尾。任何未确认资源或清理失败停止后续任务，包括允许收集普通测试失败的模式。
- 常规公共共享连接仍保持原有连接语义，受管行为由任务显式环境启用。
- `dev --open`、HTTP 打开和 engine build 共用受管入口，不能先开窗再把自己的窗口误认成借用窗口。受管打开失败向调用方传播，不继续回退或启动构建恢复。
- 没有本轮精确关闭请求证据时，后端退出或端口消失不记为窗口已关闭。关闭发送意图在 CLI 执行前落盘；已发送但结果未知、或销毁迟到时，重试只继续观察，避免再次关闭同一路径。

## 当前版本的窗口销毁证据

本轮核对的 Stable `2.02.2608070` 中，官方 `close` 返回成功只表示关闭请求已交给窗口服务。项目后端和 automator 端口先退出，原生窗口可能随后由宿主的关闭回调销毁。宿主内部的 3 秒 fallback 计时器可以取消或延迟，不能用固定等待时间判定完成。官方 CLI、HTTP 和 MCP 接口没有提供可替代的窗口销毁完成查询：项目列表返回导入项目，runtime 查询依赖已退出的后端。

受管关闭使用 `wechat-devtools-window-close-trace-v1` 记录本轮实测的主进程日志协议。关闭前只读取所选安装 `profileDir/WeappLog/logs`，保存文件身份、字节游标和游标前的内容摘要，不扫描其他安装。游标之前的日志与未完成旧行都不能成为本次证据。CLI 执行前先持久化发送意图，每次读取新增完整行后再持久化游标和已关联的窗口身份，父任务可以继续观察同一次关闭。

新增日志必须来自所选产品版本，并按以下证据关联：`native-close-call` 的 `winId`、`browserWindowId`，以及 `close-requested` 的准确项目路径、`runtimeId`。只有同一日志文件和窗口身份的 `native-window-closed`、`webcontents-destroyed`（`destroyed: true`）均出现，且 automator 端口已释放，才能将记录标为 `released`。CLI 回执在 worker 退出前未落盘时，也必须通过这组实际销毁证据完成恢复，不能重复发送关闭命令。

日志缺失、截断、替换、轮转、版本变化、关闭取消或窗口关联歧义都保留失败记录并阻断后续任务。超时仅表示尚未得到完整证据，允许下次从原游标继续观察。日志协议是本版本的验收依据，不视为微信公开稳定 API；版本升级或日志协议变化需重新验证，不能回退为仅检查端口或固定延时。

## 中断与外层入口

suite、命令序列和防休眠入口共用可重复触发的信号作用域。第一次 `SIGINT` 或 `SIGTERM` 开始收尾，后续信号不越过清理流程；退出时仅移除当前入口安装的处理函数。中断报告保留已执行任务，不继续下一项。

外层命令持有自己的项目 journal 和机器租约。Unix 关停会核实本次创建的进程组，而不只等待直接子进程退出；内层 suite 的 5 秒关停期限包含在外层 10 秒期限内。正常退出立即结束等待，只有仍活跃的本任务进程才进入强制终止。Windows 的进程树终止无法确认时保留记录并停止验收，不把主进程消失作为后代已退出的证据。

每条外层命令和每个 suite 任务获得独立的机器租约子作用域。派生凭证保留完整祖先链，登记借用者与封存作用域使用同一个变更锁。父任务先封存入口、拒绝迟到登记，再核实子树没有活跃借用者，随后回收自己的项目 journal。进程停止或窗口回收未确认时，未完成状态阻止根租约释放和后续运行接管。祖先作用域不能覆盖后代尚未确认的停止状态，也不能将外层进程组退出当作独立子任务已停止的证据。

关停回归包含真实子进程：直接父进程先退出、后代忽略终止信号，以及外层命令经 suiteRunner 启动独立任务组的取消流程。模拟时钟测试单独控制计时器，运行时关停期限保持原值，不通过放宽普通测试超时掩盖残留。

## 验证

先用聚焦回归验证断连后关闭、失败重试、重复关闭、宿主及端口身份变化、复用窗口保护、worker 异常退出和父任务停止规则。重建受影响包后，以少量真实窗口验证连续启动和回收，核对窗口及进程资源回到基线，再运行全量回归。真实结果、SDK 版本和 journal 随本轮验收记录保存。

新资源逻辑独立成模块；已有较长的 automator 和 CLI 分发文件只做接入，避免将所有权实现继续堆入启动流程。

真实资源回归脚本为 `e2e/scripts/check-devtools-project-lifecycle.ts`。它复制 `e2e-apps/base` 已构建产物，最多同时持有两个测试窗口，覆盖借用保护、断连后关闭、重复关闭、同路径重开、worker 被强制终止后的父进程回收及回执后的取消。该脚本验证 IDE 资源治理，不新增小程序运行时行为；界面窗口消失还需通过本机 IDE UI 观察核实。

基础 fixture 的两份项目配置统一固定为仓库已有的 `3.17.2` 基础库基线。旧配置 `3.15.0` 已不在本轮 IDE 的可用基础库索引中，官方版本解析会将未知版本替换为列表首项，导致实际运行 `3.17.3`。生命周期脚本继续严格比较项目配置与真实协议返回的 SDK 版本，避免把这种自动回退记为通过。
