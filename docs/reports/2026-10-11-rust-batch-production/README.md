## 采样协议与门禁

构建/HMR 使用 `native-analysis-paired-v2`、classic runtime，覆盖原生、普通 Wevu、Tailwind/TDesign 三类模板，以及组件/路由拓扑 fixture。每组固定 40 对并交替 native off/on；三类构建组与四类 HMR 组共 **560 个首批侧运行**，原生和拓扑 HMR 各追加 40 对确认，共 **160 个确认侧运行**，合计 **720**。一个构建侧运行包含首次/重复构建，一个 HMR 侧运行包含该工程全部固定编辑/恢复步骤；720 不能解释为独立编辑数，也不包括额外诊断。

全部 100 个 wall/RSS 指标样本完整，无运行错误或缺样。门禁预先固定为 `build:weapp-vite-tailwindcss-tdesign-template:repeat:wall` 的 P50 至少减少 10%；所有代表场景 wall/RSS 的 P50/P95 检查超过 5% 的回退，最多一次等量确认。200 个门禁观察项中 195 个未触发稳定回退、4 个 unstable、1 个确认 regression。未触发回退不等于获得显著收益，未更换目标或用较快轮次替换首批。

构建/HMR：2026-10-11 07:50:29–09:17:16 UTC，Darwin arm64、Node 24.18.0、Apple M4 Max、16 逻辑 CPU、128 GiB 内存；一分钟 loadavg 从 9.04 到 10.21。暖入口：07:49:33–07:50:29 UTC，同 Node/架构/逻辑 CPU，一分钟 loadavg 从 8.12 到 9.04。均为同一台共享负载机器上的配对观察，不是多机器稳定性证明。

下表变化统一为 `(on / off - 1) × 100%`，负数表示耗时或 RSS 减少。配对差值中位数为 `median(on_i - off_i)`，不是两侧中位数之差。P95 门禁在证据中使用已计算分位数的单值比较记录，不代表只采了一个样本；原始分布每侧仍为 40 个观测。

## 调用归因与测量缺口

独立暖入口诊断的 Babel wrapper 计数如下；它们不是 Vue/Oxc/Rust 的全部内部解析/遍历次数，也不是耗时占比。每例 on 侧恰好一次目标 compiler batch，无加载失败；off 侧无 native 活动。

| --- | --- | --- | --- | ---: |

| retail-detail | 157/374/28 | 156/373/28 | 1/1 | 0 |
| define-options | 7/12/1 | 6/11/1 | 1/2 | 0 |

独立故障 binding 案例另外调用一次 batch、回退一次并保持完整结果一致；其无预热调用不进入正式计时。真实 Wevu 页独立诊断 user/system CPU：off 51.885/1.906 ms、on 52.140/2.433 ms；零售页：off 77.233/2.801 ms、on 53.113/1.195 ms。零售 off 观察到一个 3.082 ms GC entry，on 为 0；Wevu 均为 0。这是各一次含 observer 成本的进程窗口，不是 40 对 CPU/GC 分布。

完整构建/HMR 的 40 对计时仅记录 wall/RSS，**没有完整 CPU/GC 配对、内部 parse/traverse/generate 次数、HMR 跨界调用或 fallback 分布**。额外 native-on 构建诊断分别在两次 CLI 生命周期合计观察到：原生 0 次调用（not-exercised）、Wevu 10 次 batch/10 个输入、Tailwind/TDesign 2 次 batch/12 个输入；后两者均 exercised，三者均无加载/执行失败和 fallback。跨界输入数不等于 parse 次数。

构建诊断 CPU 包含当前进程 worker threads，不含子进程；GC 只覆盖主 isolate 已送达与待处理 entries，不含 worker isolate/子进程，退出前尚未报告的最后一次 GC 可能遗漏。它只有 native-on 侧，不能用于宣称 CPU/GC 改善。阶段 wall 可能重叠，不能相加；GC duration 不是 CPU 时间，wall 减 CPU 不能解释为等待。计划中的全面 CPU/等待归因与跨平台性能采样尚未完成。

## 正确性、旧 transform 与交付边界

生产批量摘要对照覆盖完整返回代码、source map、告警、预期错误和故障恢复，每次预热及正式调用均校验；构建/HMR 保留产物目录内容摘要与告警对齐证据。原始宏语句的 UTF-16 范围、字符串无损表示、复杂注册保守 fallback 和批次坏项隔离均保留。结果不得因失败变成全 false 的成功摘要。

错误证据对 Babel 非枚举 `clone` 闭包比较源码、结构及三类行为探针，不按每次新建的函数引用误判；这不证明任意函数等价。未知 callable、Symbol、原型或访问器拒绝采样。进程内比较实际对象，跨进程比较完整 V8 数据快照，错误原型/描述符提前编码；稳定 tagged hash 不替代完整对照，任意用户原型方法不在该保证内。原始源码、错误栈和机器日志不进入公开附件。

旧完整 Rust script transform 在 main 合并后补齐 `nativeSlotContext` 的追加顺序与 marker 语义。8 个完整脚本执行 worker、4 对受控 Node 场景比较一致，`completed=true`、`semanticComparisonPassed=true`，来源/binding/依赖身份一致；但 `compilerComparisonPassed=false`、整体 `comparisonPassed=false`，source map 等严格编译差异仍存在。**受控语义 probe 通过不允许替代生产 Babel 转换器。**

本轮性能报告中的 headless、稳定版 IDE、真机与跨平台 performance validation 均为 not-run。Node 受控执行、产物对照和本机单测不等同于小程序宿主验收。最终 PR CI 仍待新提交验证；此前已知的 Windows 零 CPU 断言、changeset 格式、mock/准备闭包失败已有对应修复，Ubuntu Node 26 Web HMR restore 超时仍通过定向日志诊断，未降低断言或增加超时。

采样后最终本地验证：AST 单测 28/28、typecheck/ESLint；AST → @wevu/compiler → weapp-vite 顺序重建；AST `test:types:check`；`benchmark-checkout-preparation.test.ts` 3/3；串行 `e2e-hmr-infra` 的 `opened-automator.test.ts` 8/8（纯 mock，未启动 IDE）；CPU 诊断 3/3、changeset frontmatter 与相关 lint 通过。实际 compiler `check` 模式完成全部 10 个案例和单次故障回退，**性能配对为 0**。其 source/dist 哈希属于采样后校验修复版本，元数据 commit 即使仍显示冻结 SHA，也不能称为冻结版本的性能重跑。
