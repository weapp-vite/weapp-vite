# PR #1076 WXML 性能评估

标记：🔴 未通过或单批越过 5%（是否确认回退以文字结论为准）；🟢 本批耗时下降；阈值内的小幅增加保持中性。未通过项目优先标红，即使其中一次复核变快；绿色数值不代表整个 PR 通过验收。

## 范围与固定提交

本报告区分默认路径、新功能启用成本和失效恢复。新 API 在 main 上不存在，不将不存在的功能伪装成跨版本等价样本。

- 优化前：`4ca8a97b49f3a3f25d32afc5f14c2b52428d2d26`。
- 最终被测产品提交：`33c7646c5bc05272cbf496beedd233736c5d4261`。
- 中间检查点：`91ef17d64b899084814a68deed83fbed52a5da1e`（依赖索引、延迟编辑状态与 simulator 快速路径），`5504eec897c3debd0f7554dd8703332c43149b49`（独立分包源码监听恢复）。后续报告提交不改变产品源码。

同一 Node v24.18.0、darwin/arm64 环境串行运行，未并行运行仓库 E2E、构建或基准。微基准先用 esbuild 生成 ESM，依赖来自各自 checkout；不用 tsx 辅助命名的开销代表发布包。整链使用各自重建的 CLI/dist。

微基准预热 5 次、采样 15 次；公共路径另外预热 10 对、交替先后顺序采样 20 对。生产构建每模板每版本 7 次，HMR 每场景 20 次。时间单位 ms；P50/P95 使用 nearest-rank（偶数样本的 P50 是下中位数），不因结果改变统计口径。首次构建指首个测量进程，不代表操作系统文件缓存冷启动；后六次仍逐次启动构建进程。

每个样本检查产物或回调次数。GC 在微基准计时外。RSS 包含进程已加载模块和分配器高水位，堆占用包括结果/JIT/cache；不能用单次 RSS 或 GC 后堆差值证明泄漏或无泄漏。构建记录进程树 RSS，HMR 记录对应构建进程的堆与 RSS；缺失内存采样保留状态，不补零。

## 优化与工程边界

1. 外部依赖从每次登记重新汇总所有模板，改为增量引用计数。保留构建归属、处理阶段、模板隔离；失败集合去重，局部构建保留未触及模板，完整成功构建淘汰过期依赖，关闭后旧回调不能复活登记表。
2. 每轮编辑仍只扫描一次并建立父子索引；编辑句柄、属性状态、只读信息和源码位置按需创建。根节点跳过后代时不创建未访问后代的完整编辑对象；词法扫描和父子索引仍处理整份输入，skip 不承诺跳过这部分线性成本。保护规则、稳定句柄、删除失效与异步遍历不变。
3. CPU profile 显示主要成本在初始化和 GC，未证明移除 AsyncLocalStorage 或逐个等待有安全净收益，因此保留嵌套异步隔离、并发误用诊断和 skip 语义。
4. simulator 无反斜杠的普通属性直接进入 tokenizer，仅转义属性走占位恢复；不含 WXS/转义属性时省略恢复遍历。WXS 恢复循环将不变量提前计算，保持单一遍历。均未引入 native 加速。
5. 性能场景发现优化前 PR 的 classic 独立分包源码热更新丢失：关闭子 watcher 后未移交源码依赖。现在由主构建既有 sidecar watcher 和调度器接管源码/旁路依赖，失败保留恢复监听，关闭释放；产物仍由 bundler 统一发布。`independentWatch.ts` 独立承担依赖收集与生命周期，避免继续向超过 300 行的构建 service 堆积实现。
6. 默认关闭 transform/validate 时不额外扫描；validate 仅在 walk 时解析，多个回调共享本阶段扫描。transform、remove、输出插件之间不复用可能失效的解析结果。

大模板（10,001 个标签、310,013 字节）中，最终空编辑的单次堆增量中位数约 61.8 MiB，根节点跳过后代约 10.0 MiB；两者 GC 后保留增量约 0.014 MiB 与 0。该结果与懒初始化断言一致，但不是对整个运行会话的无泄漏证明。

## 生命周期、失败与不可比较项

- 8,000 个模板共享依赖只保留一个路径索引；分别登记保留 8,000 个，关闭后均为零。连续 50 轮相同依赖失败不会重复累积，恢复成功后 pending/recovery 为零，关闭后引用为零。原始微基准包含这些 evidence。
- 确定性回归验证依赖登记不枚举其他模板、懒初始化与单次扫描、稳定句柄、删除失效、只读父节点、异步嵌套与 skip、失败恢复、关闭后旧回调失效；不用易抖动的毫秒断言。
- main classic 独立分包由子 watcher 直接写盘，关闭主构建后遗留子 watcher；优化前 PR 则漏掉 classic 独立分包源码更新。前者生命周期失败，后者功能失败，均不能作为等价的通过基线。诊断与排除条件明确保留，最终统一发布有额外实际工作。
- 旧整链首次采样的优化前构建未逐次核对页面产物，仅保留历史数据；已用同一产物检查器补测 7 次/模板，不以旧样本单独证明构建通过。
- `5504eec89` 全套 400 次 HMR 无缺失和输出失败，但调用时额外启用工具的绝对 500 ms 门槛，6 个 TDesign 场景越线导致命令退出 1；main 同样有 6 个越线场景。此事实保留，不把它写成命令通过。最终成对采样采用与原比较器一致的参数，并另外核对完整样本、失败数和相对变化。
- HMR 存在会话热态和 GC/调度波动。保留所有越线首轮及复测；只脚本新会话不能替代含前置场景的整套复测，不混合两种绝对耗时。

## 🔴 验收结论：未完成全部性能验收

确认消除了依赖登记的平方增长和跳过子树时的完整编辑对象分配。原生、Wevu、Tailwind/TDesign 的默认生产构建中位数相对 main 分别为 +0.41%、+0.37%、+1.12%；30 个公共计算/渲染场景的成对中位数变化最大 +2.90%。三类代表模板的 HMR 复测未证实方向一致的稳定回退，但存在超过 5% 的单轮结果。含分包 fixture 的端到端样本也有越线，且 main 基线无法正常关闭，因此这部分不能宣称已完成 5% 的等价性能验收。

功能启用成本、classic 独立分包统一发布的明显额外延迟、旧基线的生命周期失败均已单列。新版本的关闭、连续更新、删除恢复和实际模板输出检查通过；无效或缺失基线没有被记为性能通过。glass-easel 专项适配仍延期，未改动现有 API、安全保护、异步语义或发布版本级别。
