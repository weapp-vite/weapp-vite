# Issue #1082：消除同一模板编辑的重复快照请求

在 `e0803dc451ee628244d7aad1bda97e1c627587ea` 上，源文件事件和随后到达的安全 JS patch 都请求视觉快照。若 patch 晚于 40ms 调度窗口，第二次请求会使正在编译的同一源内容失效重做；若快照已写出，则重复编译。这是调度归属重复，不能通过延长 debounce 或恢复“模板永远只含资产”的旧分类解决。

## 复现与修正

新增两项可控事件顺序回归：源事件先启动快照，JS patch 分别在快照进行中、写出后到达；修正前均为预期 1 次构建、实际 2 次。未模拟或放宽模块图的安全接受判断。

真实 CLI 诊断复用了自动导入 HMR 的 20 组件、manual 配置，执行两轮编辑/恢复，仅打开现有 snapshot trace 并保存子进程日志。原配置未关闭支持文件输出，未修改轮询、超时、marker 或最终写出方式。诊断不是三 OS 正式性能采样，耗时不作为门禁通过证据。

| 同样四次源编辑/恢复 | 修正前 | 修正后 |
| --- | ---: | ---: |
| 源事件 | 4 | 4 |
| 快照请求 | 8 | 4 |
| 快照构建 | 5 | 4 |
| 已编译但作废 | 1 | 0 |
| 资产差分发布 | 4 | 4 |

修正前首批源内容在构建前后 SHA 相同，第二次请求发生于构建期间，导致该批次在 after-build 边界被弃用。后续三次事件的重复请求虽被 debounce 合并，仍不是独立编辑。

现在由 `handleSourceUpdate` 的真实源事件统一调度视觉快照，安全 JS patch 只继续现有脚本发布，不再为同一分类请求第二次快照。保留混合模板生成脚本、模块图接受规则、后续真实源事件、快照失败保留与下一事件恢复，以及不安全更新的原有完整构建路径。

- 完整 headless 门禁 6/6 场景、37/37 DOM，包含 Wevu 新计算/事件和三类模板往返，22.48 秒。
- 真实 DevTools 3/3 场景、20/20 DOM：原生样式/脚本、资产生命周期、编辑器文件，68.70 秒；原生实例、输入、路由及事件行为保持。
- runtime 前后进程检查没有其他 E2E。临时 benchmark 日志采集改动已恢复，不改变正式基准契约；新增 weapp-vite/create-weapp-vite 中文 patch changeset。

本次证明消除了重复请求和一次真实重复构建，不能据此宣称端到端性能已满足 5% 门禁。Nightly `36275298244` 冻结旧 `e0803dc45`，其三 OS 98 项确认回退结果仍有效，不包含本修正。原真实 Wevu 首次模板失败也未因此获得通过证据，PR 继续草稿。
