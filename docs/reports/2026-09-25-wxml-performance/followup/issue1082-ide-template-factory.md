# Issue #1082：磁盘模板与 IDE 模板工厂不一致

被测 HEAD 为 `7e1ee064c43d4351754614f786ecde90a28f5fde`，产品源码仍为 `9db20cb0f`。该 HEAD 的全部 CI 已完成：31 success / 10 skipped，包括三个 OS 的 stateful headless 门禁。以下真实 IDE 诊断仍然失败，不能用 CI 通过替代最终验收。

## 控制场景

在原生 Component 页面中加入两个条件节点，明确检查初始为 1/0 个、准备后均为 0 个；模板新增与恢复两轮在 headless 和真实 DevTools 均通过 6/6 DOM。另一组控制移除原生页面的两个子组件及 usingComponents，保持原有计数、输入、身份和路由断言，两种 provider 也均通过 6/6。这些结果不能解释 Wevu 的首次更新失败，也不能将 Wevu 失败泛化成所有 Component 或条件节点均不支持热更新。

所有控制变体仅临时修改源 fixture，产物仍由正常 CLI 构建；运行后恢复原件。没有新增页面、改动正式断言或把控制场景成功算作 Issue 修复完成。

## 失败后数据与模板工厂观察

进一步只读获取 AppService 中可见的 `$gwx` 函数，并分别读取运行时数据与原生元素的文本。另一次运行启用现有 snapshot 写出诊断，同时保存失败时磁盘 WXML。没有执行模板函数、强制应用补丁或修改已安装 IDE。

## IDE 事件顺序差异

DevTools 2.02.2609231 的日志显示，原生源 WXML 在产物写出前还会产生一次缓存失效事件；SFC 源文件的 `.vue` 事件没有对应的 WXML 缓存失效分支。此前只读安装包检查确认 `.wxml` 分支清理相关 WXML 缓存，`.vue` 不执行同样的清理。

| 场景 | 源文件事件处理（UTC+8） | 模板编译调用 | 产物 WXML 事件处理 |
| --- | --- | --- | --- |
| 原生条件节点控制 | 13:26:33.860，src WXML | 13:26:34.035 / .051 | 13:26:34.528 |
| 原生无子组件控制 | 13:33:53.557，src WXML | 13:33:53.723 / .740 | 13:33:54.229 |
| Wevu 失败 | 13:50:15.146，src Vue 与 update.js | 13:50:15.600 / .608 | 13:50:16.000 |

Wevu 新 WXML 的原生写出于 13:50:15.581 完成，但 IDE 在相应合并失效事件处理前已经调用模板编译；可见工厂仍没有新增节点。原生控制则有更早的源 WXML 失效，因此不能据原生成功认定两者处于相同的 IDE 缓存条件。

这些证据把问题缩小到新磁盘内容与宿主使用的模板工厂之间。仍未直接截取编译 API 返回或渲染层注入 Promise 的结果，具体缓存/读取层与受控修复效果尚待确认。不能仅凭事件先后宣称唯一内部根因，也不通过额外源文件变更、延迟发布或强制注入把场景改成通过。
