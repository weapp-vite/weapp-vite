## 已定位的产品问题

附属 JSON 修复提交：`bf5220299daf1320d23747f028e725f9322bb619`。下述旧样本未重新标成该修复的性能结果。

独立分包的源码更新曾把主包 8 个无关入口全部标为 `snapshot-full`。d5193de5 已将独立产物发布需求与主包入口失效分开，保留统一校验、失败传播及 bundler 写盘。20 次带 CPU profile 的诊断中，中位数约 318.79 → 269.48 ms；这是先后诊断，不是正式成对验收。剩余 CPU 热点仍包括路径解析和配置/构建工作。历史基线独立子 watcher 直接写盘与统一发布语义不同，原有不可比较结论继续保留。

三平台首次 HMR 均在基线 Wevu `json-sitemap` 场景超时。本地进一步证明，恢复正常侧车监听、改用合法 `desc` 字段后，原始基线与当前产品仍都会失败。最小 watch 回归确认：扫描器知道 sitemap/theme 的路径，但 Vue App 加载后的入口记录丢失了它们，模块图仅登记了 App 脚本。

修复使加载器把**本轮 App 配置解析得到的附属 JSON 路径**直接交给入口和模块图，并在重新声明 App JSON 依赖时丢弃上一轮遗留路径。不能从扫描器直接回填旧路径，因为 classic 配置切换时扫描记录可能尚未刷新。回归覆盖 classic/stateful 的 sitemap 连续更新、恢复、theme 更新、配置切换和旧依赖清除。

固定基线的源码保持不变。该历史缺陷导致 sitemap HMR 仍不能形成原始 main/PR 的等价性能对比；新提交修复功能不等于补出了基线时间。

## 采集修正与门禁边界

- 模板、样式和 JSON 恢复必须与编辑前完整产物一致，防止空文件或局部写入窗口被误认作恢复完成。回归覆盖截断、部分内容、错误内容和 CRLF/中文。
- 正常侧车监听保持启用；显式诊断环境不能把它关闭。未通过降低正常功能成本换取性能结果。
- JSON 使用合法的标题或描述字段，不再添加任意未知字段或把 sitemap 路径替换成不存在的文件。
- 单个 HMR 场景失败会保留同轮其他已完成场景，不补零、不伪造缺失时间；一类采集失败也不会抹掉其他类别的完整证据；独立类别继续采集，完整且越线的类别仍执行唯一等量复核。任何采集错误都会阻止总门禁通过，确认回退仍标为回退。
- 没有改动 5% 阈值、没有绝对毫秒豁免、没有重新采样直到获得有利结果。历史失败及不可比较项不因其他 CI 绿色而消失。

报告渲染纠错单独交付于 [#1080](https://github.com/weapp-vite/weapp-vite/pull/1080)，已按用户授权合并；高权限自动评论只读取 main 的可信脚本，历史 Actions 摘要及原始 artifact 继续保留。
