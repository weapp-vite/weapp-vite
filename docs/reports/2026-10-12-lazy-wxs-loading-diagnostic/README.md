WXS 单测没有覆盖生产 `prepare` 的聚合模块加载次序。去掉静态 presets 后，暴露了 AST `babelCore` 适配器在模块顶层同步加载 ESM 的竞态。独立进程并发导入 Babel core 与旧适配器，可在 Node 22.22.3 和 24.18.0 复现；不同 Node 版本分别报告内部模块状态断言和 `ERR_REQUIRE_ESM_RACE_CONDITION`。修复方向是让该适配器声明静态 ESM 依赖，保持公开导出契约，不依赖 preset 偶然的导入顺序。

本报告保留规范化后的完整评估 JSON、28 份准备相关日志和原始文件哈希。`<checkout>`、`<runtime>`、`<evidence>` 仅替换本地路径；数值及错误内容不改写。完整原始采集文件与冻结运行时另行保留，本目录不是完整可移植的性能重放包。既有正式性能验收失败结论保持有效。
