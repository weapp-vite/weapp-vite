# 配置提取与 WXS 加载优化：修复后的配对冒烟

本轮通过兼容性冒烟，**尚未达到全面提速验收**。2 对样本只提供下一步定位依据，不能替代 40 对正式采样；原生脚本首次恢复仍有回退，因此本轮后不直接启动新的正式验收。

## 最终候选

- 无 JSON sidecar 的 Vue app 在路由就绪后提取一次配置；原条件下每轮 `force: true` 不变。保留初始扫描递归保护、有 sidecar 时的覆盖顺序，以及动态宏依赖重新求值。声明、逻辑组件依赖和最终 JSON 共用同一次就绪配置。
- 既有 Vue 配置缓存按实际消费源码的 UTF-16LE SHA-256 区分快照，保留路由及外部依赖 mtime 校验，隔离调用方修改；宏失败的 JSON 回退和不可克隆结果不进入缓存。源码哈希不被用于取消 app 的每轮强制求值。
- WXS 专用 Babel presets 在首次实际同步转换时加载，全部成功后才缓存；转换及错误重试契约不变。
- AST Babel core 适配器使用静态 ESM namespace import，避免 Babel 8 并行加载时的同步 `require()` 竞态，保持 default、14 项 named export 和类型契约。其他 Babel 工具继续懒加载。

前一轮候选的准备失败及 26 项告警差异完整保留在 [失败诊断](../2026-10-12-lazy-wxs-loading-diagnostic/README.md)，没有覆写。此次候选重新构建并冻结新身份。

## 采样后的兼容修订

后续复核发现，仅用源码哈希取代原 SFC mtime 校验，会让“内容不变但 touch 文件”不再触发原有宏重新求值。已补回 SFC mtime 校验：缓存同时要求实际源码哈希、SFC mtime、路由和外部依赖校验有效，不扩大动态宏缓存语义。新增回归先复现失败，修正后配置缓存、路由和上下文三个文件的 15 项测试、限定 ESLint 与包 typecheck 通过。

该兼容修订发生在采样之后，不属于 `evaluation.json` 绑定的冻结候选。修订后再次重建 weapp-vite，Node 22/24 的三类模板 prepare 共 6 次全部通过，结果与源码哈希分别保留在 `prepare-after-mtime-fix.json`、`post-smoke-source.json`。上表不能作为修订后源码的性能验收；后续需重新冻结候选。本轮对剩余 Native HMR 回退的判断及旧正式门禁失败结论均不改变。
