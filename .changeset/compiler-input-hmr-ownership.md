fix(weapp-vite): 修复编译依赖、路径别名和路由变更导致的热更新失败

共享 JSX 更新后再次修改页面时，编译器读取的组件解析、外部脚本和原生插槽元数据仍参与源码失效传播，但不再重复成为逻辑入口包装模块的脚本侧车导入，避免出现没有接受方的入口更新。

原生组件摘要的热更新边界使用一致的真实路径核对源码、根目录和已登记入口，修复临时目录及符号链接项目中的误拒绝，同时继续拒绝根目录外或未登记组件。

宿主组件解析依赖与编译器外部块依赖分别保存，修复仅更新 JSON 后丢失 barrel 失效边的问题；transform 与 bundle 通过同一入口替换 script、style、JSX 依赖及样式绑定。外部模板和样式切换或移除后，旧输入从模块图和样式图退出；模板、脚本不再错误登记为样式依赖。

Web 自动路由由当前监听器统一发布页面增删和重命名结果，并依据已发布的路由签名决定是否刷新，避免重复文件事件重置刚完成的导航。自定义 `include` 扩大监听目录时，非路由模块仍保留 Vite 的删除通知与重新创建后的错误恢复。

Web 服务启动时即注册路由监听，无需导入虚拟路由模块；页面增删由 sidecar 独占扫描与通知，避免 Vite 提前登记新增目录导致文件事件丢失。
