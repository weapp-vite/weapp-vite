# 模板标签分析对照基准

用于 #1058 的完整 `compileVueFile` 成本验证。当前编译器与同一依赖树构建两个临时版本：`shared` 使用现有单次标签分析；`duplicate-control` 仅把组件来源分析恢复为提交 `585a02c65` 的两次遍历算法。不会替换生产构建或修改源码。

```sh
node --import tsx scripts/benchmarkTemplateAnalysis/index.ts --trials=7 --output=.codex-tmp/template-analysis.json
```

默认标记为 `exploratory`。协调好独占、空闲采样窗口后才使用 `--formal`，并保留 JSON 中的完整样本、源码/输入/锁文件摘要、版本和时间。正式比较必须使用相同输入和依赖树；禁止把并发构建期间的样本改名为正式证据。

每个 trial 包含两种实现、冷/暖条件及时间/分配两种独立测量。冷条件是新进程第一次完整编译，模块导入耗时单独记录，不代表清空操作系统文件缓存。暖条件先执行两遍完整的 10/100/1000 行 SFC 套件。两种实现按 trial 交替顺序运行。

时间覆盖完整的解析、模板/脚本/样式/配置编译调用。分配在另一新进程使用 V8 HeapProfiler 16 KiB 采样，计入被 GC 回收的对象，是估计分配量。记录 GC 前后 heap、RSS 和进程峰值 RSS；峰值包含模块启动，保留堆增量包含编译输出，均不能被当成分析函数的精确独占内存。

所有条件下完整编译输出及 warning 的 SHA-256 必须相等；单次标签分析总解析次数必须为 3、历史对照必须为 6。缺失试验单元、重复 trial、非有限指标或缺失分配样本直接失败。结果不预设提速或省内存门槛，波动和无改善也必须原样报告。
